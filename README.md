`기술설계서.md`와 `구현-현황.md`가 어긋나면 **`구현-현황.md`가 최신**입니다. 바뀐 이유가 각각 적혀 있습니다.

## 실행

```
시작하기.bat 더블클릭  →  검은 창의 주소를 아이패드 Safari에 입력
```

**기록이 있는 곳이 두 모드에서 다릅니다.** 집 서버는 PC의 `data/profiles/*.json` — 같은 Wi-Fi 안 **모든 기기가 같은 기록**을 봅니다. GitHub Pages는 **각 브라우저의 localStorage** — Wi-Fi와 무관하게 **그 브라우저에서만** 보입니다. 엄마 폰으로 아이 진도를 보려면 집 서버여야 합니다 (`구현-현황.md` 32장).

친구들에게 나눠줄 때는 정적 배포를 씁니다 — `main`에 푸시하면 GitHub Pages에 자동으로 올라갑니다.
주소는 `https://{아이디}.github.io/{저장소}/`, 부모 화면은 뒤에 `parent.html`.
진행은 각자 브라우저에 남고 서버에는 아무것도 안 올라갑니다.
**처음 한 번 할 일(저장소 공개 · Pages를 GitHub Actions로)은 `깃허브-연결.md`에 있습니다.**

부모 화면은 주소 뒤에 `/parent` (PIN 기본 0000). 같은 Wi-Fi면 **부모 폰에서도 열립니다** — 6B의 사진 촬영은 폰이 아니면 안 됩니다.

## 판단이 필요할 때

- **문서에 없는 세부사항** → 기획서 2장 원칙에 비추어 판단하고, 결정한 내용을 `구현-현황.md`에 추가
- **아이가 요청한 것 vs 원칙** → 요청의 *의도*를 살리되 원칙을 지키는 형태로 변형 (스피드 모드 처리 방식이 그 예시)
- **보상 규칙을 건드릴 때** → 반드시 `node sim/60days.mjs` 먼저. 도달 불가능한 상점 단계 조건도 같이 잡아줍니다
- **AI를 붙일 때** → 기획서 원칙 2.10. AI는 **선생님**이고 조언까지 합니다 — 다만 점수는 어디에도 안 남습니다. 결정이 바뀐 경위는 `구현-현황.md` 10장
- **선생님과 친구들을 섞고 싶어질 때** → 섞지 마세요. 친구는 "나도 헷갈려", 선생님은 "이건 이래서 그래" (기획서 4.3)
- **캐릭터를 그리거나 늘릴 때** → 기획서 4.2.1의 비례 다섯 줄. 아이템 코드는 건드리지 말고 `CHARACTERS`에 앵커 세 값만 넣으세요
- **아이템을 캐릭터마다 따로 사게 하고 싶어질 때** → 하지 마세요. 검토했고 반대 근거가 `구현-현황.md` 12장에 있습니다. 늘려야 하면 **공용부터**입니다 (26.3)
- **아이템을 늘리거나 단계를 조정할 때** → 값과 단계는 **내리는 것만** 안전합니다. 1단계 선반은 13종이 하한선입니다 — 비면 목표가 아니라 품절입니다 (`구현-현황.md` 26장)
- **"같은 문제만 나온다" · "다 비슷하다"는 말이 나올 때** → 짐작하지 말고 `node sim/repeat.mjs`. 문제가 달라도 **묻는 방식이 같으면** 같은 문제로 느낍니다 (기획서 11.5.1). 가장 큰 손잡이는 코드가 아니라 **부모가 켠 단원 수**입니다
- **"너무 쉽다/어렵다"는 말이 나올 때** → 난이도 세 가지가 있습니다. 다만 **「심화」는 단원을 여러 개 켜야** 쓸 만합니다 — 부모 화면이 낼 수 있는 문제 수를 보여줍니다 (`구현-현황.md` 30.3)
- **오답을 만들거나 검사할 때** → 보기 넷은 **서로 같은 모양**이어야 합니다. 정답만 유일하게 0으로 끝나면 그건 보기가 하나인 문제입니다 (`구현-현황.md` 28.1)
- **문제 문장을 고치고 싶을 때** → 문장이 곧 그 문제의 이름입니다. 고치면 아이 진도가 0이 됩니다. 새 줄을 넣고 원래 줄을 끄세요
- **부모가 아이 별·풀을 빼고 싶어할 때** → 잘못 준 것을 되돌릴 때만입니다. 벌로 쓰면 *틀려도 손해 없다*가 깨집니다 (기획서 8.10)
- **AI 기능을 만들 때** → 이 질문 하나 — *키가 없거나 인터넷이 끊긴 상태에서 아이 화면이 평소와 똑같은가*
- **화면에 문구를 넣을 때** → *정적 모드에서도 참인가.* 코드가 갈라지지 않아도 **문구가 갈라집니다** — "아직 아이가 없습니다"가 실제로 그랬습니다 (32.2)
- **답을 직접 쓰게 할 때** → 막힌 아이가 누를 것이 화면에 있는가 (「보기 보여줘」·「모르겠어」)
- **영어 단어를 넣을 때** → `단어,뜻` 형식이면 문제 셋이 자동으로 생깁니다. 같은 파일에 **같은 단어나 같은 뜻이 둘 있으면 안 됩니다** (보기가 겹칩니다)
- **아이 학기가 바뀔 때** → `engine.js`의 `START_UNITS`. 부모가 이미 진도를 저장했으면 부모 화면에서 체크하세요

## 작업 방식

각 단계가 끝날 때마다 **실제로 돌아가는 상태**여야 합니다. 화면을 만들면 브라우저 없이도 검증할 수 있습니다 — `jsdom`으로 `app.js`를 그대로 import해 버튼을 클릭시키는 방법이 `구현-현황.md` 6장에 있습니다. 이 방식으로 별 조기 고갈, 조사 오류, 캐릭터 발견 경로 누락, 그리고 부모 화면이 통째로 죽어 있던 것을 잡았습니다.

```
node test/t_book.mjs       # 30개 — 도감. 판 보상이 줄어드는 경로가 없는지
node test/t_shop.mjs       # 43개 — 상점 단계·전용 아이템·다음 단계 미리보기
node test/t_wish.mjs       # 33개 — 배경·소원권. 받은 소원권이 사라지지 않는지
node test/t_allow.mjs      # 24개 — 용돈. 화폐가 풀인지, 주 1회인지
node test/t_units.mjs      # 132개 — 과목·단원·진도·보기 품질·난이도·유형 반복·영어 단어장·문제 파일 검산
node test/t_parent.mjs     # 37개 — 부모 화면 정리·풀 별 주기·난이도·이름
node test/t_parentrun.mjs  # 25개 — 부모 화면을 **실제로 실행**. 두 모드 다. 조용히 죽는 걸 잡는다
node test/t_backup.mjs     # 34개 — 내보내기·되돌리기·PWA
node test/t_static.mjs     # 53개 — 정적 배포. 두 모드가 갈라지지 않았는지
node sim/60days.mjs 180    # 보상 균형. 가격표를 characters.js·backgrounds.js에서 그대로 읽는다
node sim/repeat.mjs        # 문제·유형 반복과 난이도별 비중. "또 이거" 소리가 나오면 이것부터
```

5A 때 쓰던 `t_engine.mjs`·`t_app.mjs`는 저장소에 없습니다. 없는 채로 진행하기로 했으니, 손으로 확인할 것을 각 단계마다 정해두고 시작하세요. 특히 6A(채점 규칙)는 눈으로 다 못 봅니다.

`t_book.mjs`는 **jsdom 없이** 돕니다 — `app.js`에서 순수 함수만 떼어 검사하는 방식입니다. 5B의 나머지도 같은 방식으로 붙일 수 있습니다.

`characters.js`는 렌더링만이라도 검사할 수 있습니다 (`구현-현황.md` 11.5).

```
cp web/characters.js /tmp/ch.mjs && node --input-type=module -e "import('/tmp/ch.mjs').then(m=>{
  for (const c of m.CHARACTERS) console.log(c.id,
    m.charSVG(c.id,{hat:'crown',neck:'rain'},'').includes('NaN') ? 'BAD' : 'OK') })"
```

`app.js`를 일괄 치환으로 수정할 때는 **치환 대상이 파일에 정확히 한 번만 있는지 확인**하세요. 한 번 범위를 잘못 잡아 파일이 깨진 적이 있습니다.

**부모 화면은 조용히 죽습니다.** ES 모듈이라 최상위에서 에러가 나면 그 아래가 통째로 안 돌고, 에러는 화면 어디에도 안 뜹니다. 부모가 보는 것은 `불러오는 중…` 넉 줄뿐입니다. 두 번 났습니다 — import 이름(2.12), 선언 순서(29장). 이제 **`node test/t_parentrun.mjs`가 실제로 실행해봅니다.** `parent.html`을 건드렸으면 이것부터 돌리세요.

**모듈 최상위 상태(`let`/`const`)는 반드시 화면을 그리기 전에 선언하세요.** `let`은 끌어올려지지 않습니다 — 아래에 선언하고 위에서 읽으면 화면이 통째로 얼어붙습니다.

## 첫 작업 지시 예시

> `기획서.md` 12장과 `구현-현황.md` 9장을 읽고, 6A 단답형을 만들어줘.
> `유형` 열(기술설계서 5.6)부터 `packs.py`에 넣고, 그 다음 입력 화면이야.
> **「보기 보여줘」와 「모르겠어」를 같이 넣어줘** — 막힌 아이가 누를 게 없으면 안 돼.
> 입력창에 `spellcheck=false`를 빼먹지 마. 빨간 밑줄은 원칙 2.1 위반이야.
