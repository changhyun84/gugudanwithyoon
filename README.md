# 양이랑 구구단 v2

가정용 학습 게임입니다. 초등 3학년 아이 한 명을 위해 만들었고, 집 PC에서 띄워 아이패드로 접속해 사용합니다.
**v2는 5A단계까지 완성되어 실사용 중입니다.**

## 새 대화에서 이어받는 분께

아래 순서로 읽으세요.

| 순서 | 문서 | 내용 |
|---|---|---|
| 1 | `기획서.md` | 배경, **절대 원칙(가장 중요)**, 기능 정의, 보상 경제 |
| 2 | `구현-현황.md` | **지금까지 만든 것과 설계서에서 바뀐 결정** |
| 3 | `기술설계서.md` | 아키텍처, API, 스키마, 파일 포맷, 구현 순서 |
| 4 | `문제-만들기-안내.md` | 부모가 문제를 등록하는 방법 (사용자 매뉴얼) |

문서는 전부 `docs/` 안에 있습니다. 아래 두 개는 표에서 참조하지만 **아직 저장소에 없습니다** — `설치-실행-안내.md`, `깃허브-연결.md`.

`기획서.md`의 **2장 "절대 원칙"은 협상 대상이 아닙니다.** 이 아이는 틀리는 것을 부끄러워해서 어른 앞에서 구구단 묻기를 거부했던 아이입니다. 게임이 성공한 이유는 재미가 아니라 *아무도 안 보고, 틀려도 손해가 없어서*입니다. 재미나 학습 효율을 이유로 원칙을 깎지 마세요.

`기술설계서.md`와 `구현-현황.md`가 어긋나면 **`구현-현황.md`가 최신**입니다. 바뀐 이유가 각각 적혀 있습니다.

## 판단이 필요할 때

- **문서에 없는 세부사항** → 기획서 2장 원칙에 비추어 판단하고, 결정한 내용을 `구현-현황.md`에 추가
- **아이가 요청한 것 vs 원칙** → 요청의 *의도*를 살리되 원칙을 지키는 형태로 변형 (스피드 모드 처리 방식이 그 예시)
- **보상 규칙을 건드릴 때** → 반드시 `node sim/60days.mjs` 먼저. 도달 불가능한 상점 단계 조건도 같이 잡아줍니다
- **AI를 붙일 때** → 기획서 원칙 2.10. AI는 **선생님**이고 조언까지 합니다 — 다만 점수는 어디에도 안 남습니다. 결정이 바뀐 경위는 `구현-현황.md` 10장
- **선생님과 친구들을 섞고 싶어질 때** → 섞지 마세요. 친구는 "나도 헷갈려", 선생님은 "이건 이래서 그래" (기획서 4.3)
- **캐릭터를 그리거나 늘릴 때** → 기획서 4.2.1의 비례 다섯 줄. 아이템 코드는 건드리지 말고 `CHARACTERS`에 앵커 세 값만 넣으세요
- **아이템을 캐릭터마다 따로 사게 하고 싶어질 때** → 하지 마세요. 검토했고 반대 근거가 `구현-현황.md` 12장에 있습니다. 늘려야 하면 **전용 아이템**으로
- **AI 기능을 만들 때** → 이 질문 하나 — *키가 없거나 인터넷이 끊긴 상태에서 아이 화면이 평소와 똑같은가*
- **답을 직접 쓰게 할 때** → 막힌 아이가 누를 것이 화면에 있는가 (「보기 보여줘」·「모르겠어」)

## 작업 방식

각 단계가 끝날 때마다 **실제로 돌아가는 상태**여야 합니다. 화면을 만들면 브라우저 없이도 검증할 수 있습니다 — `jsdom`으로 `app.js`를 그대로 import해 버튼을 클릭시키는 방법이 `구현-현황.md` 6장에 있습니다. 이 방식으로 별 조기 고갈, 조사 오류, 캐릭터 발견 경로 누락, 그리고 부모 화면이 통째로 죽어 있던 것을 잡았습니다.

```
node test/t_book.mjs       # 30개 — 도감. 판 보상이 줄어드는 경로가 없는지
node test/t_shop.mjs       # 31개 — 상점 단계·전용 아이템. 선반이 닫히는 경로가 없는지
node test/t_wish.mjs       # 33개 — 배경·소원권. 받은 소원권이 사라지지 않는지
node test/t_allow.mjs      # 24개 — 용돈. 화폐가 풀인지, 주 1회인지
node test/t_units.mjs      # 24개 — 과목·단원 스캔. 팩 id가 안 바뀌는지
node sim/60days.mjs 180    # 보상 균형. 가격표를 characters.js·backgrounds.js에서 그대로 읽는다
```

5A 때 쓰던 `t_engine.mjs`·`t_app.mjs`는 저장소에 없습니다. 없는 채로 진행하기로 했으니, 손으로 확인할 것을 각 단계마다 정해두고 시작하세요. 특히 6A(채점 규칙)는 눈으로 다 못 봅니다.

`t_book.mjs`는 **jsdom 없이** 돕니다 — `app.js`에서 순수 함수만 떼어 검사하는 방식입니다. 5B의 나머지도 같은 방식으로 붙일 수 있습니다.

`characters.js`는 렌더링만이라도 검사할 수 있습니다 (`구현-현황.md` 11.5).

```
cp web/characters.js /tmp/ch.mjs && node --input-type=module -e "import('/tmp/ch.mjs').then(m=>{
  for (const c of m.CHARACTERS) console.log(c.id,
    m.charSVG(c.id,{hat:'crown',neck:'rain'},'').includes('NaN') ? 'BAD' : 'OK') })"
```

`app.js`를 일괄 치환으로 수정할 때는 **치환 대상이 파일에 정확히 한 번만 있는지 확인**하세요. 한 번 범위를 잘못 잡아 파일이 깨진 적이 있습니다.

`parent.html`이 `engine.js`에서 import하는 이름을 바꾸거나 지우면 **부모 화면 스크립트 전체가 조용히 죽습니다.** ES 모듈은 링크 단계에서 실패하고 에러도 화면에 안 보입니다. 잡아주던 테스트가 없으니, `engine.js`의 export를 건드렸으면 **부모 화면을 직접 열어보세요.**

## 첫 작업 지시 예시

> `기획서.md` 16장과 `구현-현황.md` 18·19장을 읽고, 5C-2를 만들어줘.
> 프로필에 `progress` 필드를 넣고 `buildIndex(packs, disabled, progress)`로 거르면 돼.
> **`disabled`와 합치지 마** — `progress`가 없으면 뒤에 새 파일을 넣는 순간 열려버려.
> 과목이 `progress`에 없으면 **첫 단원만** 열려야 해.
