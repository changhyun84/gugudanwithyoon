# 양이랑 구구단 v2 — 기술설계서

`기획서.md`를 먼저 읽으세요. 이 문서는 그 기획을 구현하는 방법만 다룹니다.

---

## 1. 제약과 선택

| 제약 | 결정 |
|---|---|
| 집 PC에서 부모가 직접 실행 | **의존성 0.** 설치할 게 적을수록 좋음 |
| 아이패드에서 접속 | 로컬 네트워크 HTTP 서버 필요 |
| 데이터를 PC의 JSON 파일에 저장 | 정적 서버로는 불가 → 쓰기 가능한 API 필요 |
| 가정 내 사용, 외부 노출 없음 | 인증은 부모 화면 PIN 정도로 충분 |
| 부모가 문제 파일을 폴더에 넣음 | 서버가 폴더를 스캔 |

**스택: Python 3 표준 라이브러리만.** `http.server` + `json` + `csv`. 외부 패키지 없음.

macOS에는 Python이 기본 설치되어 있고, Windows는 Microsoft Store에서 한 번만 설치하면 됩니다. Node.js로 만들면 npm install 단계가 생기는데, 부모가 직접 운영하는 환경에서는 그 한 단계가 실패 지점이 됩니다.

> 프레임워크(Flask/Express)를 쓰고 싶은 유혹이 있겠지만, 이 규모(엔드포인트 8개)에서는 이득보다 설치 부담이 큽니다.

## 3. 서버

### 3.1 실행

```bash
python3 server.py            # 기본 포트 8770
python3 server.py --port 9000
```

- `0.0.0.0`에 바인딩 (아이패드에서 접속해야 하므로)
- 시작 시 **접속 주소를 크게 출력** — 부모가 이걸 보고 아이패드에 입력합니다

```
────────────────────────────────────────
  양이랑 구구단이 켜졌습니다

  아이패드에서 아래 주소로 들어가세요
      http://192.168.0.14:8770

  부모 화면
      http://192.168.0.14:8770/parent

  끄려면 이 창에서 Ctrl+C
────────────────────────────────────────
```

IP는 `socket.socket(AF_INET, SOCK_DGRAM)`으로 외부 주소에 connect한 뒤 `getsockname()`으로 얻습니다(실제 전송 없음). 여러 개면 전부 출력합니다.

### 3.2 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/bootstrap` | 프로필 목록 + 설정 + 문제 팩 메타 + 메시지 (첫 로드 1회) |
| GET | `/api/pack/:id` | 팩 하나의 문제 전체 |
| GET | `/api/profile/:id` | 프로필 JSON |
| PUT | `/api/profile/:id` | 프로필 저장 |
| POST | `/api/profile` | 새 프로필 생성 |
| GET | `/api/parent/packs` | 팩 목록 + 파싱 경고 (PIN 필요) |
| PUT | `/api/parent/settings` | 설정 저장 (PIN 필요) |

PIN은 `X-Parent-Pin` 헤더로 전달. `data/settings.json`에 저장, 기본 `0000`.

AI 확장에서 추가되는 것은 **세 개뿐**입니다. 자세한 것은 12·13장.

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/ai/reply` | 서술형 답에 캐릭터 반응 (아이 화면. **PIN 없음, 키도 안 나감**) |
| POST | `/api/parent/scan` | 사진 → 단어 목록 (PIN) |
| POST | `/api/parent/pack` | 검토를 마친 목록을 CSV 파일로 저장 (PIN) |

### 3.3 저장 정책

- 클라이언트는 **문제 1개 풀 때마다가 아니라 5문제마다 + 화면 전환 시 + 세션 종료 시** 저장 (요청 폭주 방지)
- `visibilitychange`와 `pagehide`에서도 저장 — 아이패드는 홈 버튼을 누르면 그냥 사라집니다. `navigator.sendBeacon` 사용
- **원자적 쓰기 필수**: 임시 파일에 쓰고 `os.replace()`. 중간에 PC가 꺼져도 파일이 깨지지 않습니다
- 하루 첫 저장 시 `data/backups/{id}-{날짜}.json`으로 자동 백업, **최근 30개만 보관**하고 오래된 건 삭제

> 아이가 몇 주 모은 아이템이 날아가면 타격이 큽니다. 백업은 선택 기능이 아니라 필수입니다.

### 3.4 보안

가정 내 로컬 네트워크 전용입니다. 다음만 지킵니다.

- 정적 파일 서빙 시 **경로 탈출 차단** (`..` 정규화 후 `web/` 하위인지 확인)
- 프로필 id는 `[가-힣a-zA-Z0-9_-]{1,20}`만 허용 — 파일명으로 쓰이므로 필수
- 요청 본문 크기 상한 (1MB)
- 인터넷에 포트포워딩하지 말 것을 README에 명시

#### 전용 아이템은 스키마를 바꾸지 않습니다 (기획서 8.7)

`inventory.items`는 지금처럼 **산 것의 id 목록 하나**입니다. 캐릭터별로 나누지 않습니다.

```jsonc
"inventory": { "items": ["straw", "crown", "rbow", "cmoon"] }
//                                      ↑토끼전용  ↑고양이전용 — 같은 배열에 섞여 있다
```

누구 것인지는 **아이템 정의에 적혀 있으므로**(`only: 'rabbit'`) 프로필에 다시 적을 필요가 없습니다. 화면에서 거르면 됩니다.

이 선택 덕분에 `buy()`·`wearGrid()`·`inventory`가 구조 그대로입니다. 전용 아이템 때문에 저장 형식이 바뀌면 이미 산 것을 옮겨 심어야 하고, 그 마이그레이션이 실패하면 **아이가 몇 주 모은 물건이 사라집니다.**

`equipped`에 `prop` 슬롯을 실제로 씁니다. 값이 없던 프로필은 `null`로 읽히므로 마이그레이션이 필요 없습니다.

`history`는 최근 90일만 보관하고 앞에서부터 잘라냅니다.

## 5. 문제 팩 파일 포맷

`content/problems/` 폴더의 `.csv`와 `.md`를 스캔합니다. **파일명이 팩 이름, 파일명 슬러그가 팩 id**입니다.

### 5.1 CSV

UTF-8, 첫 줄은 헤더. **엑셀에서 저장할 때 "CSV UTF-8"을 골라야 한글이 안 깨집니다** — 부모 안내에 반드시 포함.

```csv
문제,정답,오답1,오답2,오답3,힌트,묶음
7 × 8,56,48,54,63,7×4는 28. 두 배 하면?,7단
6 × 7,42,,,,6×3은 18. 두 배 하면?,7단
24 ÷ 6,4,,,,6을 몇 번 더하면 24?,나눗셈
```

- `오답1~3`이 비면 **자동 생성** (5.3)
- `힌트`가 비면 힌트 버튼 미표시
- `묶음`은 통계/자유 모드 필터용, 비어도 됨
- `유형` 열로 답하는 방식을 고릅니다 — 없거나 비면 `선택` (5.6)
- 열 순서가 달라도 **헤더 이름으로 매칭**합니다. 부모가 열을 옮길 수 있으므로 위치 고정 금지
- 영어 헤더(`question,answer,wrong1,...`)도 함께 인식

### 5.2 Markdown

메모장으로도 쓸 수 있는 가벼운 형식입니다.

```markdown
# 3학년 나눗셈

묶음: 나눗셈

- 24 ÷ 6 = ?  ->  4  // 6을 몇 번 더하면 24가 될까?
- 35 ÷ 5 = ?  ->  7
- 48 ÷ 8 = ?  ->  6  // 8×6을 떠올려봐
```

파싱 규칙:
- `#` 줄 = 팩 표시 이름 (없으면 파일명)
- `묶음:` 줄 = 이 파일 전체의 기본 묶음
- `-` 로 시작하는 줄이 문제
- `->` 또는 `→` 앞이 문제, 뒤가 정답
- `//` 뒤는 힌트
- 오답 보기는 지정 불가 → 항상 자동 생성 (형식을 단순하게 유지하기 위한 의도적 제약)

### 5.3 오답 보기 자동 생성

정답이 정수일 때:

```
후보 = [정답±1, 정답±2, 정답±10, 정답의 자릿수 바꿈,
        정답±(정답의 약수 중 하나)]
```

여기서 중복·음수·정답과 같은 값을 걸러내고 3개를 무작위로 뽑습니다. 부족하면 정답 ±(1~9) 랜덤으로 채웁니다.

내장 구구단 팩은 v1의 로직을 그대로 씁니다 — `a×(b±1)`, `(a±1)×b` 같은 **실제로 아이가 헷갈리는 값**이 나와서 더 좋은 오답이 됩니다.

### 5.4 문제 id

`{팩id}:{정규화한 문제 문자열}`. 문제 텍스트에서 공백을 제거하고 소문자화한 값입니다.

파일을 수정해도 문제 텍스트가 그대로면 진행이 유지됩니다. 문제 텍스트를 고치면 새 문제로 취급됩니다 — 이 동작을 부모 안내에 적어둡니다.

### 5.5 오류 처리

**형식이 틀린 줄이 있어도 팩 전체를 버리지 않습니다.** 읽을 수 있는 줄만 싣고, 실패한 줄은 경고 목록에 모아 `/api/parent/packs`로 내보냅니다. 부모 화면에 이렇게 보여줍니다.

> `3학년-나눗셈.md` — 문제 24개를 읽었습니다. 7번째 줄은 정답을 찾을 수 없어 건너뛰었습니다.

아이 화면에는 오류를 절대 노출하지 않습니다.

### 5.6 유형 열 — 답하는 방식

기획서 12장의 구현입니다. `HEADERS`에 `type: ['유형', 'type']`을 더합니다.

| 값 | 별칭 | 문제 객체 `type` |
|---|---|---|
| (비어 있음) · `선택` | `객관식`, `choice` | `choice` |
| `단답` | `주관식`, `short` | `short` |
| `서술` | `open` | `open` |

모르는 값이 오면 **`choice`로 떨어뜨리고 경고에 남깁니다.** 오타 하나로 문제가 사라지면 안 됩니다.

```csv
문제,정답,오답1,오답2,오답3,힌트,묶음,유형
7 × 8,56,48,54,63,,7단,
apple,사과,,,,,9월2주,
사과,apple,,,,a로 시작해,9월2주,단답
식물이 물을 빨아들이는 곳은 어디일까? 왜 그렇게 생각해?,뿌리,,,,,식물,서술
```

MD 파일은 파일 전체에 한 줄로 겁니다 — `묶음:`과 같은 자리입니다.

```markdown
# 9월 2주 영단어
묶음: 9월2주
유형: 단답
```

#### 파서에서 달라지는 것

| 유형 | `choices` | `answer` | 비고 |
|---|---|---|---|
| `choice` | 4개 (현행) | 필수 | 지금 그대로 |
| `short` | **4개 그대로 만듭니다** | 필수 | 「보기 보여줘」용 예비 |
| `open` | 만들지 않음 | 선택 (없어도 됨) | `answer`는 참고 답안 |

`short`에서도 보기를 만들어 두는 것이 핵심입니다. 「보기 보여줘」를 누르는 순간 4지선다로 바뀌어야 하는데, 그때 서버를 다시 부를 수 없습니다. 보기 4개를 못 만들면(5.3 실패) **그 문제는 `choice`가 아니라 `short`로 남기고, 「보기 보여줘」 버튼만 감춥니다.** 지금은 보기를 못 만들면 문제를 통째로 뺐지만, 단답형에는 그럴 이유가 없습니다.

`open`은 `answer`가 비어도 통과시켜야 합니다. `parse_csv`의 `if not question or not answer` 검사에 `type == 'open'` 예외를 넣습니다 — **여기를 놓치면 서술형 문제가 전부 경고로 버려집니다.**

#### 복수 정답과 관대한 채점 (`short`)

정답 칸에 `/`로 나눠 적으면 전부 정답입니다 — `빛/빛깔`.

판정은 **클라이언트**(`engine.js`)에서 합니다. 서버는 문자열만 넘깁니다.

```js
const norm = s => String(s).trim().toLowerCase()
  .replace(/\s+/g, ' ')                     // 여분 공백
  .replace(/^(a|an|the)\s+/, '')            // 영어 관사
  .replace(/[.,!?~]+$/, '');                // 끝 문장부호

const isRight = (input, answer) =>
  String(answer).split('/').map(norm).includes(norm(input));
```

한글 조사는 **자동 보정하지 않습니다.** "뿌리를"과 "뿌리"를 규칙으로 가르려다 "빨래"를 "빨" + 조사로 잘못 자르는 편이 더 나쁩니다. 복수 정답으로 적게 하고, `문제-만들기-안내.md`에 그렇게 적습니다.

## 7. 출제 엔진

v1 로직을 팩 개념으로 일반화합니다.

### 7.1 마스터리

문제마다 `m` 값 0~4를 둡니다.

| 결과 | 변화 |
|---|---|
| 힌트 없이 정답 | `m + 1` (최대 4) |
| 힌트 쓰고 정답 | `m`이 0이면 1로, 아니면 유지 |
| 오답 | `m - 1` (최소 0) |

`m`이 4에 도달하면 마스터 — 별 1, 스티커 1을 주고 `masteredAt` 기록.

유형이 늘어도 **이 표는 바뀌지 않습니다.** 새 입력 방식을 기존 세 결과 중 하나로 옮겨 놓기만 합니다.

| 단답형에서 일어난 일 | 기존 규칙 중 무엇으로 | 왜 |
|---|---|---|
| 직접 써서 맞힘 | 힌트 없이 정답 (`m+1`) | 인출에 성공했습니다 |
| 「보기 보여줘」 쓰고 맞힘 | **힌트 쓰고 정답** (`m`이 0이면 1) | 힌트와 같은 성격입니다 (원칙 2.3) |
| 틀림 · 「모르겠어」 | 오답 (`m-1`) | |
| 서술형 | **아무것도 안 함** | `facts` 항목 자체가 없습니다 |

`applyResult()`의 인자 `usedHint`에 「보기 보여줘」를 함께 넣으면 그대로 동작합니다. **엔진에 새 분기를 만들지 마세요.**

### 7.2 활성 문제

`m < 3`인 문제 중 팩 순서상 **앞에서 3개만** 열립니다. 나머지 미학습 문제는 가중치 0으로 잠깁니다.

한 번에 3개씩만 새로 배우게 하는 것이 v1에서 잘 작동한 핵심입니다. 유지하세요.

### 7.3 가중 추첨

```
w(문제) =
  미학습 & 활성   → 14
  미학습 & 비활성 → 0     (잠금)
  m = 1           → 8
  m = 2           → 3.5
  m = 3           → 1.6
  m = 4           → 0.8   (마스터해도 가끔 복습)

직전 문제는 제외
3일 이상 안 본 문제는 ×1.5
```

마스터한 문제가 낮은 가중치로 계속 섞이는 것이 **자신감 유지 + 간격 반복**을 동시에 해결합니다.

### 7.4 모드별 차이

| 모드 | 출제 대상 | 문제 수 | 유형 |
|---|---|---|---|
| 천천히 | 위 가중 추첨 전체 | 하루 목표까지 | 전부 (`open`은 하루 2개) |
| 다시 만나기 | `m ≤ 1` 인 것만, 없으면 `m ≤ 2` | 10 | `choice`·`short` |
| 스피드 | `m ≥ 3` 인 것만 | 60초 | **`choice`만** |
| 자유 | 선택한 팩 안에서 가중 추첨 | 하루 목표까지 | 전부 (`open`은 하루 2개) |

유형은 모드가 아니라 **문제의 속성**입니다(기획서 6.5). 아이가 유형을 고르는 화면은 없습니다.

`open`은 `facts`가 없어 가중 추첨에 못 들어갑니다. **따로 뽑습니다** — `daily.writings < 2`이면 `open` 목록에서 하나를 끼워 넣고, 아니면 없는 것처럼 취급합니다. `pickKey()`에 `open`을 섞으려 하지 마세요. 마스터리가 없는 것을 가중치로 다루려면 예외가 엔진 전체로 번집니다.

스피드가 `choice`만인 이유: 60초 안에 글자를 치게 하면 6.3의 "실패 경험이 구조적으로 발생하지 않는다"가 깨집니다. 오타가 곧 실패가 됩니다.

## 8A. 캐릭터와 아이템 (`characters.js`)

기획서 4.2·8.7의 구현입니다.

### 8A.1 앵커에 배율

아이템 SVG는 **양 기준 좌표 한 벌**입니다(모자 100,30 / 목 100,96). 캐릭터마다 앵커점으로 옮기고 배율만큼 키웁니다.

```js
// anchor: [x, y, 배율]  — 배율은 생략하면 1
{ id: 'cat', anchor: { hat: [100, 46, 1.28], neck: [100, 111, 1.26] } }

function place(svg, anchor, base) {
  const [ax, ay, s = 1] = anchor, [bx, by] = base;
  if (ax === bx && ay === by && s === 1) return svg;
  return `<g transform="translate(${ax},${ay}) scale(${s}) translate(${-bx},${-by})">${svg}</g>`;
}
```

`translate(a) scale(s) translate(-b)`는 **b점을 a로 보내면서 a를 중심으로 s배** 합니다. 순서를 바꾸면 원점 기준으로 커져서 아이템이 화면 밖으로 날아갑니다.

새 캐릭터를 추가할 때 **아이템 코드는 건드리지 말고** `CHARACTERS`에 앵커 세 값만 넣으세요.

### 8A.2 아이템 정의

```js
export const HATS = [
  { id: 'straw', nm: '밀짚모자', price: 90,  tier: 1 },
  { id: 'rbow',  nm: '귀 리본',  price: 260, tier: 3, only: 'rabbit' }
];
export const PROPS = [ /* 소품 — 슬롯을 새로 엽니다 */ ];
```

| 필드 | 뜻 |
|---|---|
| `tier` | 몇 단계에서 열리는지 (기획서 8.3). 없으면 1 |
| `only` | 이 캐릭터만. **없으면 공용** |

두 필드 다 **없을 때가 기본**이라 기존 13개는 한 줄도 안 고쳐도 됩니다.

### 8A.3 상점·옷장에서 거르는 규칙

```js
const buyable = it =>
  (it.tier || 1) <= P.shopTier &&
  (!it.only || P.characters.unlocked.includes(it.only));

const wearable = (it, charId) => !it.only || it.only === charId;
```

- **상점** — `buyable`. 아직 못 만난 친구의 전용 아이템은 안 보입니다(기획서 8.7)
- **옷장** — 가진 것 중 `wearable`. 토끼 리본은 토끼일 때만 목록에 뜹니다
- **미리보기** — 전용은 `charSVG(it.only, ...)`로 **그 캐릭터에 씌워** 보여줍니다. 활동 캐릭터에 씌우면 못 입는 물건이 입은 것처럼 보입니다

옷장에서 안 보이는 것은 **가진 것이 사라진 게 아닙니다.** 캐릭터를 바꾸면 다시 나타납니다. 그래도 아이 입장에서 헷갈릴 수 있으니, 전용 아이템에는 그 친구 이름을 작게 붙입니다 — *"토끼만"*.

### 8A.4 슬롯

`equipped: { hat, neck, prop }` 셋입니다. `isHat(id)`로 두 갈래를 나누던 코드가 세 갈래가 되므로 **슬롯 판정을 아이템 정의로 옮기세요.**

```js
// 지금:  worn()[isHat(id) ? 'hat' : 'neck'] = id
// 바꿔:  worn()[slotOf(id)] = id
```

`slotOf`가 한 곳에 있으면 슬롯을 또 늘릴 때 고칠 곳이 하나입니다.

## 12. AI 연동 (`ai.py`)

기획서 13장의 구현입니다. **선택 기능이고, 없으면 게임은 그대로 돕니다.**

### 12.1 왜 의존성이 안 늘어나는가

1장의 "표준 라이브러리만"을 깨지 않습니다. Gemini는 REST + JSON이라 `urllib.request`로 부릅니다.

```python
import json, urllib.request, urllib.error

def call(api_key, model, parts, timeout=8):
    url = (f'https://generativelanguage.googleapis.com/v1beta/'
           f'models/{model}:generateContent')
    body = json.dumps({'contents': [{'parts': parts}],
                       'generationConfig': {'temperature': 0.7, 'maxOutputTokens': 200}}).encode()
    req = urllib.request.Request(url, data=body, method='POST', headers={
        'Content-Type': 'application/json', 'x-goog-api-key': api_key})
    with urllib.request.urlopen(req, timeout=timeout) as res:
        return json.load(res)
```

`google-generativeai` 패키지를 쓰지 마세요. `pip install` 한 줄이 이 프로젝트의 제일 큰 제약을 깹니다.

**`ai.py`는 새 파일입니다.** `server.py`에 넣지 않습니다 — 지금까지 서버는 파일만 다뤘고, 그 단순함이 고장을 줄여 왔습니다. 외부 호출은 실패하는 코드이므로 격리합니다.

모델 id는 **설정값**입니다. 코드에 박지 마세요 — 무료 등급에서 쓸 수 있는 모델은 바뀝니다. 기본값은 그 시점의 무료 flash 계열로 두고, 부모 화면에서 고칠 수 있게 합니다.

### 12.2 설정

```jsonc
// data/settings.json
"ai": {
  "key": "",                       // 비어 있으면 AI 기능 전체가 꺼짐
  "model": "gemini-2.5-flash",     // 무료 등급에서 쓸 수 있는 것으로 부모가 고침
  "advice": true,                  // 선생님이 조언까지 할지 (기획서 13.1.1). 기본 켜짐
  "teacherName": "",               // 아이가 지어준 이름. 비면 "선생님"
  "dailyLimit": 40,                // 하루 호출 상한 (서버가 강제)
  "usedToday": 0, "usedDay": "",   // 상한 카운터
  "logKeep": 50                    // 부모 화면에 보여줄 최근 기록 수
}
```

`key`는 **`/api/bootstrap`의 `public_settings()`에 절대 넣지 않습니다.** 지금 `public_settings()`가 화이트리스트 방식(`speedModeEnabled`, `defaultGoal`만 골라 담기)인 것이 다행입니다 — **이 방식을 유지하세요.** `{**settings}` 같은 전개로 바꾸면 그날 키가 아이패드로 새어 나갑니다.

아이 화면에는 `aiEnabled: bool`만 내려갑니다. `bool(key)`의 결과입니다.

### 12.3 `POST /api/ai/reply` — 서술형 반응

아이 화면이 부릅니다. **PIN이 없습니다** — 아이가 PIN을 알 수 없기 때문입니다. 대신 이렇게 좁힙니다.

- 받는 것은 `{ packId, key, text }`뿐입니다. **캐릭터를 받지 않습니다** — 서술형의 화자는 언제나 선생님이라 클라이언트가 정할 여지를 두지 않습니다
- `key`가 **현재 색인에 있고 유형이 `open`인 문제**여야 합니다. 아니면 400
- `text`는 600자에서 자릅니다
- 하루 상한을 넘으면 **200에 `{ reply: null }`** 을 돌려줍니다. 오류가 아닙니다
- 프로필 id·아이 이름은 **받지도 않습니다.** 보낼 수가 없어야 합니다

```jsonc
// 응답 — 어떤 경우에도 200
{ "reply": "맞아, 뿌리야. 흙에 있으니까 물을 만나기 좋지." }
{ "reply": null }    // 키 없음 / 상한 초과 / 타임아웃 / API 오류 — 아이 화면은 구분하지 않음
```

`reply`가 `null`이면 클라이언트는 `messages.csv`의 준비된 문장을 씁니다. **오류 화면·재시도 버튼을 만들지 마세요.**

#### 프롬프트 — 선생님 페르소나

기획서 2.10과 4.3의 구현입니다. **페르소나가 안전장치의 본체입니다.** 같은 문장도 부모가 말하면 지적이 되고 선생님이 말하면 배움이 되기 때문에, 역할을 정확히 심는 것이 금지어 목록보다 중요합니다.

```
너는 초등학교 3학년 아이의 학습 게임에 나오는 선생님이야.
아이가 믿고 따르는 다정한 선생님이고, 아이가 무엇을 쓰든 실망하지 않아.
한국어로 두세 문장. 쉬운 말로.

문제: {문제}
아이가 쓴 답: {아이 답}
참고 답안: {정답}          ← 파일에 있을 때만

이렇게 말해:
1. 먼저 아이가 쓴 것에서 잘한 부분을 구체적으로 짚어줘. 뭉뚱그리지 말고 아이가 쓴 말을 그대로 인용해
2. {조언}

하지 말아야 할 것:
- 점수, 등급, 몇 점 같은 평가
- "부족해요", "아쉽네요", "조금만 더" 같은 말
- 다시 써 보라고 하기
- 틀린 부분을 여러 개 나열하기
- 맞춤법이나 띄어쓰기 고쳐주기
- 어제와 비교하거나 다른 아이와 비교하기
- 아이 답이 참고 답안과 달라도 틀렸다고 하지 마
```

`{조언}` 자리는 스위치(기획서 13.1.1)에 따라 둘 중 하나가 들어갑니다.

| 스위치 | `{조언}` 자리에 넣는 문장 |
|---|---|
| **켜짐** (기본) | `그 다음에, 다음에 해볼 것을 딱 한 가지만 제안해. 명령이 아니라 "~해보는 것도 재밌어" 같은 권유로. 아이가 빠뜨린 개념이 있으면 여기서 쉽게 설명해줘.` |
| 꺼짐 | `그걸로 끝이야. 더 하라고 제안하지 마.` |

**한 가지만**을 프롬프트에 못 박는 것이 중요합니다. 두 개를 말하는 순간 조언이 지적 목록이 됩니다.

선생님의 이름을 아이가 지어줬으면 프롬프트에 넣습니다. **아이 이름은 넣지 않습니다** — 프로필 객체를 `ai.py`에 넘기지 않으면 실수할 방법이 없습니다.

#### 응답 검열 — 프롬프트만 믿지 않습니다

```python
BANNED = ['점수', '몇 점', '등급', '부족', '아쉽', '틀렸', '오답',
          '맞춤법', '띄어쓰기', '다시 써', '다시 한번', '다시 적어']
if any(w in reply for w in BANNED) or len(reply) > 220:
    return None          # 준비된 문장으로 폴백
```

**조언을 허용하면서 목록에서 뺀 것들이 있습니다.** 원래 있던 `훌륭`·`노력`은 뺐습니다 — 선생님이 "훌륭한 생각이야"라고 못 하면 칭찬 자체가 막힙니다. `점이`도 `점이 좋아` 같은 정상 문장을 잡아서 `몇 점`으로 좁혔습니다.

남긴 것은 전부 **실패를 확인시키거나 재작성을 요구하는 말**입니다. 이 기준으로 늘리고 줄이세요.

길이 상한은 조언이 붙으므로 160 → 220입니다. 그래도 상한은 필요합니다 — 길어지면 그 자체가 훈계로 읽힙니다.

걸리면 조용히 `null`입니다. 부모 화면 로그에는 "규칙에 걸려 쓰지 않음"으로 남겨 프롬프트를 고칠 수 있게 합니다.

> 검열은 **최후의 그물**이지 설계가 아닙니다. 금지어를 피해 가는 지적 문장은 얼마든지 가능합니다.
> 진짜 안전장치는 페르소나이고, 진짜 확인 방법은 **부모가 로그의 조언 문장을 직접 읽는 것**입니다(12.5).

#### 아이 화면의 순서 — 이 순서가 전부입니다

```
1. 아이가 「다 썼어」를 누른다
2. 풀 지급 · writings 저장 · 이야기 스티커 · 선생님이 준비된 문장으로 말함 · 「다음」 버튼 활성
   ────── 여기까지가 완결. 아래는 전부 덤 ──────
3. 백그라운드로 /api/ai/reply 호출
4. 3초 안에 오면 말풍선 내용만 슬쩍 바뀐다. 늦거나 실패하면 아무 일도 없다
5. 아이가 이미 다음으로 넘어갔으면 응답을 버린다
```

로딩 스피너를 넣지 마세요. **기다림을 만드는 순간 실패할 수 있는 화면이 됩니다.**

말풍선이 바뀔 때 **글자가 갑자기 튀지 않게** 합니다. 준비된 문장이 한 줄인데 조언이 붙어 세 줄로 늘어나면 화면이 덜컹거립니다. 말풍선 높이를 미리 확보하거나, 짧은 페이드로 갈아 끼우세요. 아이 눈에는 선생님이 처음부터 그렇게 말한 것처럼 보여야 합니다.

### 12.4 스레드와 타임아웃

`ThreadingHTTPServer`라 외부 호출이 다른 요청을 막지는 않습니다. 다만:

- `urlopen(timeout=8)`을 **반드시** 겁니다. 없으면 스레드가 영원히 남습니다
- 아이 화면 쪽에서도 `AbortController`로 5초에 끊습니다
- 동시 호출은 서술형이 하루 2문제라 문제가 안 됩니다. 상한이 그 자체로 보호 장치입니다

### 12.5 부모 화면 로그

`data/ai-log.jsonl`에 한 줄씩 붙입니다(최근 `logKeep`개만 유지).

```jsonc
{"at":"2026-09-03 19:20", "kind":"reply", "prompt":"...", "text":"...",
 "reply":"...", "advice":true, "ok":true, "blocked":null, "ms":1840}
```

부모가 **무엇이 오갔는지 전부 볼 수 있어야** 합니다. 조언을 허용한 뒤로는 이게 더 중요해졌습니다 — **선생님이 원칙 2.10을 지키고 있는지 확인할 수 있는 유일한 창**입니다. 금지어 검열은 최후의 그물일 뿐이고, 그물을 빠져나가는 지적 문장은 사람이 읽어야 보입니다.

부모 화면에서는 **조언 문장만 따로 모아 보는 목록**을 하나 두세요. 한 주에 열 줄 남짓이라 훑는 데 1분이면 됩니다. 여기서 어색한 문장이 보이면 프롬프트를 고치거나 조언 스위치를 끕니다.

## 13. 사진으로 단어 등록 (6B)

기획서 14장의 구현입니다. **부모 화면 전용, 아이 화면 변화 0.**

### 13.1 흐름

```
부모 폰 브라우저에서 /parent 접속 (같은 Wi-Fi)
  → <input type="file" accept="image/*" capture="environment"> 로 촬영
  → 브라우저에서 긴 변 1600px로 축소, JPEG 품질 0.8, base64
  → POST /api/parent/scan
  → 서버가 Gemini에 이미지 + 지시문 전송
  → 표로 표시 (단어 / 뜻 / 확신 없음 표시)
  → 부모가 고치고 지우고 추가
  → POST /api/parent/pack  →  content/problems/{파일명}.csv 저장
```

축소를 브라우저에서 하는 이유는 `MAX_BODY`가 1MB이기 때문입니다. 요즘 폰 사진 원본은 3~8MB라 **그냥 보내면 잘려서 실패합니다.** `canvas.toBlob`으로 줄입니다. `/api/parent/scan`에 한해 상한을 6MB로 올리는 방법도 있지만, 축소가 정확도도 더 좋습니다(글자가 작아도 됨).

### 13.2 `POST /api/parent/scan`

```jsonc
// 요청 (PIN)
{ "image": "data:image/jpeg;base64,...", "mode": "영단어" }

// 응답 — 실패해도 200, 이유를 담아서
{ "ok": true,
  "rows": [ { "q": "apple", "a": "사과", "sure": true },
            { "q": "purpose", "a": "목적", "sure": false } ] }

{ "ok": false, "why": "API 키가 없습니다. 설정에서 넣어주세요." }
{ "ok": false, "why": "글자를 찾지 못했습니다. 밝은 곳에서 다시 찍어보세요." }
```

`sure: false`는 표에서 **눈에 띄게 표시**합니다. 흐릿한 글자·손글씨·번호와 붙은 단어에서 나옵니다.

지시문에 넣을 것:

- 번호(`1.`, `①`), 체크박스, 밑줄 같은 장식을 빼고 단어만
- 한 줄에 여러 단어가 있으면 나눔
- 파생형(`-s`, `-ed`)이 아니라 **사진에 적힌 그대로**
- 못 읽겠으면 지어내지 말고 `sure: false`
- **응답은 JSON 배열만.** 설명 문장 금지

JSON 파싱에 실패하면 (모델이 ```` ```json ```` 으로 감싸는 일이 흔합니다) 코드펜스를 벗기고 한 번 더 시도하고, 그래도 안 되면 `ok: false`입니다. **부분적으로 읽은 것을 억지로 쓰지 않습니다.**

### 13.3 `POST /api/parent/pack` — 검토 결과 저장

```jsonc
{ "filename": "9월2주-영단어", "group": "9월2주", "type": "선택",
  "rows": [ { "q": "apple", "a": "사과" }, ... ],
  "overwrite": false }
```

- `filename`은 `ID_RE`와 같은 문자 집합만 허용하고 `.csv`를 붙입니다. **경로 탈출 차단은 프로필 id와 같은 수준으로** 겁니다 — 여기가 처음으로 *부모가 준 문자열로 파일을 만드는* 자리입니다
- 같은 이름이 있으면 `overwrite: false`일 때 409. 덮어쓰기는 부모가 한 번 더 확인해야 합니다
- 저장 형식은 **기존 CSV 그대로**입니다. 새 포맷을 만들지 않습니다. 저장한 뒤에는 손으로 만든 파일과 구별되지 않고, 엑셀로 열어 고칠 수 있어야 합니다
- 저장 직후 `packs.scan()`을 한 번 돌려 **경고가 없는지 확인하고 돌려줍니다.** 방금 만든 파일이 안 읽히면 그 자리에서 알아야 합니다

### 13.4 영↔한 양방향

한 장의 사진에서 방향이 다른 파일 두 개까지 만들 수 있게 합니다.

| 파일 | 문제 | 정답 | 유형 |
|---|---|---|---|
| `9월2주-영단어.csv` | `apple` | 사과 | 선택 |
| `9월2주-영단어-쓰기.csv` | 사과 | `apple` | 단답 |

**한꺼번에 만들되 「쓰기」는 꺼진 채로 저장하는 것**을 권합니다(`disabled.packs`). 아이가 영→한을 마스터한 뒤 부모가 켜면, 아이 입장에서는 새 팩이 열린 사건이 됩니다.

오답 보기는 `묶음`이 같은 다른 뜻에서 나옵니다(`구현-현황.md` 2.2). 그래서 **한 번 찍은 한 장 = 한 묶음**이 되게 파일을 나눕니다. 20~30개면 보기 품질이 충분합니다.

### 13.5 이 기능이 실패하는 방식

| 실패 | 결과 | 대비 |
|---|---|---|
| 사진이 흐림 | 엉뚱한 단어 | `sure: false` 표시 + 부모 검토 필수 |
| 키 없음·쿼터 초과 | 인식 안 됨 | 부모 화면에 이유 표시. 손으로 CSV를 쓰는 길은 그대로 남아 있음 |
| 모델이 설명을 덧붙임 | JSON 파싱 실패 | 코드펜스 제거 후 재시도, 실패 시 `ok:false` |
| 부모가 확인을 건너뜀 | **틀린 문제가 아이에게 감** | 확인 없이 저장되는 경로를 아예 안 만듦 |

마지막 줄이 이 기능의 유일한 절대 조건입니다.
