# 양이랑 구구단 v2 — 기획서

## 1. 배경

초등 3학년 아이가 구구단을 "칠일은 칠, 칠이 십사…" 노래로만 외웠습니다. 7×8을 물으면 7×1부터 순서대로 세어야 답이 나옵니다. 무작위 인출이 안 되는 상태입니다.

v1은 그 압박을 없애는 데 초점을 맞췄고 성공했습니다. 재미있게 아이가 스스로 하겠다고 합니다.

v2는 **이 성공 조건을 유지한 채** 오래 쓸 수 있게 확장하는 작업입니다.

---

## 2. 절대 원칙 — 변경 금지

이 원칙들은 재미나 학습 효율을 이유로 완화하지 않습니다. 새 기능을 넣을 때마다 이 목록에 비추어 검토하세요.

### 2.1 실패를 눈에 보이게 만들지 않는다

금지: 빨간색 오답 표시, X 마크, 실패음, 하트/목숨 차감, 화폐 차감, 연속 정답(스트릭) 카운터, 콤보, "다시 도전" 화면.

오답은 조용한 파란 톤으로 정답과 방법만 알려주고 넘어갑니다.

### 2.2 보상은 '푼 것'에 준다

문제를 풀면 무조건 기본 보상. 정답은 그 위에 얹는 보너스입니다. 아이가 *틀릴까 봐 시작하지 않는 상태*로 돌아가면 안 됩니다.

### 2.3 힌트는 무료다

힌트를 봐도 기본 보상은 동일합니다. 모를 때 도움을 요청해도 된다는 것을 배우는 편이 정답 하나보다 중요합니다. (정답 보너스만 소폭 차등)

### 2.4 기본 모드에 시간 제한이 없다

"천천히 해도 괜찮아"는 화면에 상시 노출합니다. 속도를 칭찬하지 않습니다. — 스피드 모드는 6.3의 조건을 모두 만족할 때만 예외.

### 2.5 하루에는 끝이 있다

목표를 채우면 "오늘 끝! 내일 또 보자"로 닫습니다. 무한 반복은 놀이를 노동으로 바꿉니다. 더 하고 싶어하면 허용하되, 먼저 권하지 않습니다.

### 2.6 약한 문제에 라벨을 붙이지 않는다

"네가 틀린 문제", "취약 단원" 같은 표현을 아이 화면에 절대 노출하지 않습니다. 약한 문제는 **며칠 뒤 자연스럽게 다시 등장**시키기만 합니다.

### 2.7 어른의 실시간 감시가 없다

정답률·소요시간 같은 통계는 부모 화면에만 둡니다. 아이 화면에서 부모 화면으로 가는 경로를 만들지 않습니다(별도 URL + PIN). 아이가 "이 숫자를 어른이 본다"고 인식하는 순간 압박이 되살아납니다.

### 2.8 남과 비교하지 않는다

랭킹, 친구 점수, 또래 평균, 학년 백분위 — 전부 만들지 않습니다. 비교 대상은 오직 **어제의 자신**입니다.

### 2.9 응원 메시지 규칙

- 속도를 칭찬하지 않는다 ("빠르다!" 금지)
- 오답 메시지에서 위로하지 않는다 ("괜찮아, 다음엔 잘할 거야"는 실패를 확인시킵니다)
- 대신 태연하게 정보만: *"아, 이건 56이야. 나도 이거 자꾸 헷갈리더라."*
- 어른도 헷갈린다는 것을 캐릭터가 자주 보여줍니다

### 2.10 AI는 채점하지 않는다 — 대신 가르친다

서술형을 위해 외부 AI를 붙입니다. **역할은 채점자가 아니라 선생님입니다.**

#### 이 원칙이 왜 이렇게 정해졌나 (2026-08-19, 부모 관찰)

처음에는 AI가 반응만 하고 조언은 일절 안 하는 쪽으로 설계했습니다. 어른의 지적이 아이를 다시 조용하게 만들까 봐서였습니다.

그런데 부모가 관찰한 것이 있습니다.

> 아이가 자신감이 붙었습니다. 그리고 **부모의 지적은 부끄러워하지만, 선생님의 지시는 기꺼이 따르고 오히려 안정감을 얻습니다.**

이건 이 아이에 대한 관찰이고, 설계보다 강한 근거입니다. 그래서 조언을 허용합니다.

핵심은 **누가 말하느냐**입니다. 같은 문장도 부모가 말하면 지적이 되고 선생님이 말하면 배움이 됩니다. 부모는 평가하는 사람이고 선생님은 가르치는 사람이라고 아이가 이미 알고 있기 때문입니다. AI에게 **선생님 페르소나**를 입히는 것이 안전장치의 본체입니다.

#### 허용

- 아이가 쓴 것에서 **잘한 부분을 먼저 짚기**
- 그 다음 **한 가지만** 조언하기 — "다음엔 ~도 같이 생각해보면 재밌어"
- 빠진 개념을 설명해주기
- 다음에 해볼 구체적인 것 하나 제안하기

#### 여전히 금지

| 금지 | 이유 |
|---|---|
| 점수·등급·별점·"몇 점" | 숫자 평가는 비교를 부릅니다 (2.8) |
| "부족해요 / 아쉽네요 / 조금만 더" | 실패를 확인시킵니다 (2.1) |
| 다시 써 오라는 요구 | 재작성 요구는 곧 불합격 판정입니다 |
| 틀린 부분을 목록으로 나열하기 | 오답 노트가 됩니다 (10장) |
| 맞춤법·띄어쓰기 교정 | 고치기 시작하면 **아이가 쓰는 양이 줄어듭니다** |
| 어제와 비교, 다른 아이와 비교 | 2.8 |
| 실망하거나 서운해하기 | 선생님은 아이가 한 줄만 써도 똑같이 반응합니다 |

#### 조언의 세 가지 형식 규칙

1. **한 번에 하나.** 두 개를 말하면 조언이 아니라 지적 목록이 됩니다
2. **잘한 것 다음에.** 순서가 바뀌면 칭찬이 조언의 포장지가 됩니다
3. **명령형이 아니라 제안형.** "이렇게 써"가 아니라 "이렇게 해보는 것도 재밌어"

#### 끌 수 있어야 합니다

조언은 **부모가 끌 수 있습니다.** 근거가 "요즘 아이가 자신감이 붙었다"는 관찰이고, 관찰은 바뀔 수 있기 때문입니다. 아이가 서술형을 피하기 시작하면 조언을 먼저 끄고, 그래도 안 되면 AI를 끕니다.

#### 순서는 그대로입니다

보상은 **쓴 순간 이미 지급**되어 있어야 합니다(2.2). 선생님의 말은 그 뒤에 도착하고, 늦거나 실패하면 준비된 문장으로 대신합니다. 아이 화면에 오류·대기를 노출하지 않습니다.

> 무엇을 붙이든 이 질문 하나로 판정하세요 — **"이 화면이 아이를 다시 조용하게 만드는가?"**
> 조언을 허용해도 이 질문은 그대로입니다. 답이 바뀌었을 뿐입니다.

## 4. 캐릭터

### 4.1 구성

| 캐릭터 | 해금 | 성격 / 말투 |
|---|---|---|
| 양 | 기본 제공 | 다정하고 차분함. 안심시키는 역할 |
| 고양이 | 별 8 | 시크한 츤데레. 인정에 인색한 척하지만 챙김 |
| 토끼 | 별 15 | 활발하고 신남. 단, 속도가 아니라 시도를 칭찬 |
| 코알라 | 별 25 | 늘 졸림. 느긋함이 곧 "서두를 필요 없다"는 메시지 |
| 카피바라 | 별 40 | 초연하고 태평. 실수를 대수롭지 않게 넘김 |

해금한 캐릭터는 **홈 화면 목장에 함께 등장**합니다. 아이가 화면을 열 때마다 늘어난 식구가 보이는 것이 장기 동기의 핵심입니다.

활동 캐릭터(문제 풀 때 옆에서 응원하는 역할)는 하나를 선택합니다. 캐릭터마다 이름을 따로 지어줄 수 있습니다.

### 4.2 그리기

v1의 양처럼 **인라인 SVG로 직접 그립니다.** 이미지 파일 의존 없음, 크기 자유, 모자/목도리 레이어 합성 가능.

캐릭터마다 착용 앵커 좌표(모자 위치, 목 위치)를 정의해 아이템 SVG를 공용으로 씁니다. 앵커만 다르고 아이템 코드는 하나입니다.

```
CHARACTERS = [
  { id: 'sheep', anchor: { hat: [100, 30],       neck: [100, 96] } },
  { id: 'cat',   anchor: { hat: [100, 46, 1.28], neck: [100, 111, 1.26] } },
  ...
]
```

**세 번째 값은 배율입니다.** 캐릭터마다 머리 크기가 다르면 같은 모자가 어떤 애한테는 헬멧, 어떤 애한테는 챙 없는 모자가 됩니다. 앵커점을 중심으로 키워서 맞춥니다. 생략하면 1입니다.

배율이 있으면 **그림체를 캐릭터마다 자유롭게 하면서도 아이템 한 벌을 계속 공용으로 쓸 수 있습니다.** 이게 4.2의 핵심입니다 — 호환을 위해 그림을 똑같이 그릴 필요가 없습니다.

### 4.2.1 귀여움의 기준 (2026-08-19)

처음에 다섯을 같은 템플릿에 색만 바꿔 그렸더니 **양만 괜찮고 나머지 넷이 밋밋했습니다.** 호환을 위해 그림체를 맞춘 것이 원인이었습니다. 앵커에 배율을 더해 그 제약을 풀고 넷을 다시 그렸습니다.

넷에 공통으로 적용한 규칙입니다. 캐릭터를 더 늘릴 때도 이대로 하세요.

| | 왜 |
|---|---|
| **머리를 몸보다 크게** | 2등신이 아기 비례입니다. 얼굴 `rx 40`, 몸통 `rx 36~40` |
| **눈을 얼굴 아래쪽 1/3로** | 아기 얼굴은 눈이 한가운데가 아니라 아래에 있습니다. 이게 가장 큰 차이입니다 |
| **눈을 크고 멀리** | 반지름 9, 하이라이트는 **큰 것 + 작은 것 두 개** |
| **다리 넷 대신 앞발 둘** | 넷은 어른 동물, 둘은 아기처럼 보입니다 |
| **볼터치는 전원** | 고양이·코알라처럼 차가운 색일수록 필요합니다 |

**양은 손대지 않았습니다.** v1부터 아이가 좋아한 그림입니다.

정체성은 비례보다 우선합니다 — 카피바라의 네모난 얼굴은 모서리만 둥글게 굴리고 유지했습니다. 둥글게 만들면 귀여워지지만 카피바라가 아니게 됩니다.

### 4.3 선생님 — 목장 식구가 아닙니다

원칙 2.10에서 AI에게 입히는 페르소나입니다. **앞의 다섯과 역할이 정반대이므로 섞지 않습니다.**

| | 친구들 (양·고양이·토끼·코알라·카피바라) | 선생님 |
|---|---|---|
| 하는 말 | "나도 이거 자꾸 헷갈리더라" | "이건 이래서 그런 거야" |
| 관계 | 옆에 있는 또래 | 가르쳐주는 어른 |
| 역할 | **안심** — 틀려도 괜찮다 | **배움** — 다음에 뭘 해볼지 |
| 어디 있나 | 목장 (홈 화면) | 서술형을 풀 때만 |
| 해금 | 별 8~40 | **해금 없음.** 서술형을 처음 만나면 나옴 |
| 활동 캐릭터로 고를 수 있나 | 예 | **아니오** |
| 꾸미기 | 모자·목도리 | 없음 |

친구들을 선생님으로 만들면 안 됩니다. "어른도 헷갈린다"를 보여주는 것이 그들의 존재 이유이고(2.9), 그게 v1이 성공한 이유입니다. 반대로 선생님이 "나도 몰라"라고 하면 아이가 기대는 안정감이 사라집니다. **둘 다 필요하고, 둘은 다른 곳에 있어야 합니다.**

- **부엉이**를 권합니다. 아이들 이야기에서 이미 선생님 자리에 있는 동물이라 설명이 필요 없습니다
- 목장에 오지 않습니다. 서술형 화면에만 있습니다. **장소가 다르면 역할이 헷갈리지 않습니다**
- 이름은 아이가 지어줄 수 있습니다
- 말투: 차분하고, 아는 것을 아는 대로 말하고, 서두르지 않고, **실망하지 않습니다**

> 왜 해금을 안 거는가 — 선생님은 보상이 아니라 기능입니다. 별로 잠가두면 서술형 자체가 잠깁니다.

## 5. 응원 메시지

### 5.1 동작

문제를 맞히면 활동 캐릭터가 말풍선으로 한마디 합니다. 상황별 풀에서 무작위로 뽑되 **최근 5개는 다시 뽑지 않습니다**(반복은 금방 질립니다).

### 5.2 상황 구분

| 코드 | 언제 | 톤 |
|---|---|---|
| `정답` | 맞혔을 때 | 인정. 속도 언급 금지 |
| `힌트정답` | 힌트 쓰고 맞혔을 때 | 힌트 쓴 걸 긍정 |
| `오답` | 틀렸을 때 | 태연. 위로 금지, 정보 전달 |
| `시작` | 세션 시작 | 편안하게 |
| `끝` | 목표 달성 | 축하 |
| `새아이템` | 구매/해금 | 신남 |
| `오랜만` | 3일 이상 쉬고 접속 | 반가움. 죄책감 유발 금지 |
| `마스터` | 문제 하나 완전 습득 | 성취 인정 |
| `글쓰기` | 서술형을 쓰고 냈을 때 | 선생님 전용. AI가 꺼졌을 때의 대사 |

`글쓰기`는 캐릭터가 **`선생님`** 인 줄만 씁니다(4.3). 어떤 글에도 어색하지 않아야 하므로 내용을 언급하지 않습니다.

### 5.3 편집

`content/messages.csv`에서 부모가 직접 추가·수정합니다. 아이 이름이나 집안 농담을 넣으면 효과가 큽니다. 형식은 `기술설계서.md` 6장 참고.

기본 메시지는 캐릭터당 상황별 6개 이상을 미리 넣어둡니다.

## 6. 게임 모드

### 6.1 천천히 모드 (기본)

v1과 동일. 시간 제한 없음, 하루 목표까지 진행. 이것이 언제나 기본값이고 홈 화면의 가장 큰 버튼입니다.

### 6.2 반복 모드

약해진 문제만 모아 **10문제 짧게** 진행합니다. 화면에는 "약한 문제"라고 쓰지 않고 **"다시 만나기"** 로 표기합니다(원칙 2.6).

보상은 문제당 기본 풀 + 별도 소액 보너스. 짧고 자주 하도록 유도합니다.

### 6.3 스피드 모드 (조건부)

아이가 요청한 기능이지만 원칙 2.4와 부딪힙니다. **다음 조건을 모두 만족할 때만** 제공합니다.

1. **기본값 꺼짐.** 부모가 `/parent` 설정에서 켜야 나타납니다.
2. **이미 마스터한 문제만 출제.** 마스터리 3 이상인 문제가 20개 넘게 쌓여야 켤 수 있습니다. 아는 것만 나오므로 실패 경험이 구조적으로 발생하지 않습니다.
3. **틀려도 감점·중단 없음.** 그냥 다음 문제로 넘어갑니다.
4. **비교 대상은 자기 기록뿐.** "내 최고 12개" 외의 어떤 비교도 없습니다.
5. **결과 화면에 실패가 없음.** 항상 "N개 풀었어"로 끝납니다. 기록을 못 넘겨도 "오늘도 N개"입니다.
6. 60초 고정, 하루 3회 제한(과열 방지).

> 이 기능을 넣을 때는 부모에게 짧은 안내를 띄웁니다: *아이가 부담스러워하는 기색이 보이면 바로 끄세요.*

### 6.4 자유 모드

특정 문제 팩만 골라서 풉니다. 시험 대비처럼 부모가 특정 범위를 지정하고 싶을 때 씁니다.

### 6.5 문제 유형은 모드가 아닙니다

단답형·서술형(12장)은 **새 모드가 아니라 문제의 속성**입니다. 어느 모드에서든 섞여 나옵니다. 아이가 "오늘은 단답형 할래"를 고르는 화면은 만들지 않습니다 — 유형을 고르게 하면 어려운 유형을 영영 안 고릅니다.

| 모드 | 유형이 어떻게 섞이나 |
|---|---|
| 천천히 | 팩에 적힌 대로 전부. 서술형은 **하루 2문제까지** |
| 다시 만나기 | 선택·단답만. 서술형은 마스터리가 없어 "약해진 문제"가 없습니다 |
| 스피드 | **선택형만.** 시간 제한 안에서 글자를 치게 하면 원칙 2.4의 예외 조건이 무너집니다 |
| 자유 | 고른 팩에 있는 대로 |

서술형 하루 2문제 상한은 **모드가 아니라 하루 단위**로 셉니다. 천천히 모드에서 2개를 쓰고 자유 모드로 넘어가면 그날은 더 안 나옵니다.

## 7. 문제 팩

### 7.1 종류

- **내장 팩** — 구구단(v1 로직 이식). 코드에 포함, 삭제 불가
- **부모 작성 팩** — `content/problems/` 폴더에 CSV 또는 MD 파일을 넣으면 자동 인식

### 7.2 요구사항

- 엑셀에서 만들 수 있어야 함 (CSV)
- 메모장에서도 만들 수 있어야 함 (MD)
- 오답 보기를 안 적으면 **자동 생성**
- 힌트는 선택 사항
- 파일을 저장하면 서버 재시작 없이 반영 (요청 시마다 폴더 스캔)
- 형식이 틀린 줄은 게임을 죽이지 않고 **부모 화면에 경고로 표시**

상세 스펙은 `기술설계서.md` 5장, 사용법은 `문제-만들기-안내.md`.

### 7.3 답하는 방식

팩의 문제마다 **답하는 방식**을 고를 수 있습니다. `선택`(보기 4개, 기본) · `단답`(직접 입력) · `서술`(문장으로 씀).

12장에서 자세히 다룹니다. 파일에 아무것도 안 적으면 지금까지처럼 전부 `선택`이라 **기존 팩은 그대로 동작합니다.**

## 8. 보상 경제

v1의 문제: 화폐가 하나뿐이라 왕관(450풀)을 사면 더 살 게 없습니다. 약 3주면 고갈됩니다. v2는 **6~10주 이상** 유지되도록 설계합니다.

### 8.1 두 가지 화폐

| | 풀 🌿 | 별 ⭐ |
|---|---|---|
| 성격 | 일상 화폐, 매일 벌림 | 희귀 화폐, 성취로만 |
| 획득 | 문제당 3, 정답 시 +3 | 아래 8.2 참고 |
| 용도 | 모자·목도리·소품 | 캐릭터 해금, 배경 |
| 하루 수급 | 약 90~120 | 0~3 |

풀은 매일 쌓이므로 "오늘도 뭔가 벌었다"는 감각을 줍니다. 별은 드물게 나오므로 캐릭터 해금이 사건이 됩니다.

### 8.2 별 획득 경로

| 조건 | 별 |
|---|---|
| 문제 하나 완전 습득 (마스터리 4 도달) | 1 |
| 팩 하나 전체 마스터 | 5 |
| 7일 누적 출석 (연속 아님 — 원칙 2.1) | 3 |
| 도감 한 판 완성 | 3 |

> **연속 출석 보상은 만들지 않습니다.** 하루 빠졌을 때 끊기는 것이 곧 실패 경험이 됩니다. 누적으로만 셉니다.

### 8.3 상점 단계 개방

전 상품을 처음부터 보여주면 목표가 흐려지고, 다 사면 끝납니다. **누적 마스터 문제 수**에 따라 재고가 열립니다.

| 단계 | 조건 | 열리는 것 | 총액 |
|---|---|---|---|
| 1 | 시작 | 공용 모자 3, 목도리 3 (60~120풀) | 520 |
| 2 | 10문제 마스터 | 공용 모자 4, 목도리 3, **소품 2** (160~450풀) | 2,350 |
| 3 | 25문제 마스터 | **전용 모자** 캐릭터당 1 (220~340풀) | 1,400 |
| 4 | 50문제 마스터 | **전용 목도리** 캐릭터당 1 (360~500풀) | 2,150 |
| 5 | **65문제 마스터** | **전용 소품** 캐릭터당 1 (520~700풀) | 3,030 |

새 단계가 열릴 때 홈 화면에 알림을 띄웁니다. 이것이 다음 목표가 됩니다.

전체 **9,450풀**(30종)입니다. 60일 수입이 약 6,000이므로 8주가 지나도 살 것이 남습니다(11장 성공 기준 2). 개별 구매 없이 이 숫자를 만든 방법은 8.7에 있습니다.

> 3단계부터는 **해금한 캐릭터 수만큼만** 열립니다. 별로 친구를 만나면 풀 쓸 곳이 같이 늘어나는 구조라, 두 화폐가 서로를 밀어줍니다.

> **5단계 조건이 80 → 65로 내려갔습니다 (2026-08-19).** 지금 문제 파일로는 별을 주는 문제가 **75개뿐**이라 80은 도달할 수 없었습니다. 조건을 정할 때는 `node sim/60days.mjs`가 도달 가능한지 먼저 알려줍니다. **조건을 올리지 마세요** — 이미 열린 단계가 닫히면 어제까지 살 수 있던 물건이 사라집니다(원칙 2.1).

### 8.4 도감 (스티커 판)

문제 하나를 마스터할 때마다 스티커 한 장을 얻어 판에 붙입니다. 판 하나는 12칸이고, 채우면 별 3.

**학습 진도가 곧 컬렉션**이 되는 구조라 "다 모으고 싶다"가 "다 외우고 싶다"와 같은 뜻이 됩니다. 장기 동기로는 이게 상점보다 강합니다.

### 8.5 배경 (별 소비처)

목장 배경을 별로 삽니다. 낮/노을/밤/눈/벚꽃 등 **10종**, 각 별 5~12 (누적 83). 캐릭터 해금 사이의 별 소비처 역할을 합니다.

처음에 5~8종으로 잡았는데 시뮬레이션에서 **50일쯤 별 쓸 곳이 다 사라졌습니다.** 배경을 늘려도 결국 마르므로, 8장의 결론은 그대로입니다 — **고갈되지 않는 소비처는 소원권뿐**입니다. 배경은 소원권이 들어오기 전까지 버티는 역할입니다.

기본 배경은 계절과 시간에 따라 **무료로 자동 변화**시켜 지루함을 줄입니다.

### 8.8 소원권 (별 소비처의 끝)

아이스크림, 늦게 자기, 저녁 메뉴 정하기 같은 **실물 보상**을 별로 바꿉니다.

`content/wishes.csv`로 부모가 등록합니다 — 문제 팩·메시지와 같은 방식이라 **파일이 없으면 기능 자체가 안 나타납니다.** 그것이 "기본 꺼짐"입니다.

```csv
소원,별,설명
아이스크림 사러 가기,8,아무 때나 쓸 수 있어
같이 영화 보기,20,팝콘도 같이
```

#### 왜 별인가

소원권은 **드물고 사건이어야** 합니다. 관계형 보상이라 비교나 환산이 안 됩니다. 반대로 용돈은 풀입니다 — 풀은 '푼 것'에 주므로 **틀려도 용돈이 나옵니다**(원칙 2.2). 용돈을 별로 사게 하면 별은 마스터(=정답)에만 붙으므로 "틀리면 돈을 못 번다"가 됩니다.

#### 받은 소원권은 지우지 않습니다

"썼다" 표시를 만들지 않습니다. 아이가 실수로 눌러 날릴 수 있고, **사라지는 것은 회수처럼 느껴집니다**(원칙 2.1). 들어준 뒤에도 목록에 남습니다.

같은 소원을 여러 번 바꿀 수 있습니다. 부모 화면에서 무엇을 몇 번 바꿔갔는지 봅니다.

### 8.9 용돈 (풀 소비처의 끝)

풀 🌿을 진짜 돈으로 바꿉니다. **별이 아니라 풀입니다.**

| | 화폐 | 이유 |
|---|---|---|
| 소원권 | ⭐ 별 | 드물고 사건이어야 함. 관계형 보상이라 비교·환산이 안 됨 |
| 용돈 | 🌿 풀 | 풀은 '푼 것'에 주므로 **틀려도 용돈이 나옵니다** (원칙 2.2) |

용돈을 별로 사게 하면 별은 마스터(=정답)에만 붙으므로 **"틀리면 돈을 못 번다"** 가 됩니다. 이 게임이 통한 이유가 정확히 그 반대입니다.

#### 주 1회, 정한 요일에만

매일 환전되면 임금이 되고, **임금이 되면 놀이가 노동이 됩니다**(원칙 2.5). 요일을 정해두면 그날이 작은 사건이 되고, 나머지 엿새는 그냥 노는 날입니다.

한 번에 바꿀 수 있는 양에도 상한을 둡니다. 상한이 없으면 아이가 모은 풀을 전부 돈으로 바꿔버려서 **가게에 살 것이 있어도 못 삽니다.** 두 소비처가 서로를 잡아먹지 않게 하는 장치입니다.

#### 설정은 부모 화면에 (파일이 아니라)

소원권과 달리 `/parent` 설정입니다. 실제 돈이므로 PIN 뒤에 두는 편이 맞습니다. 기본은 꺼짐이고, 부모가 환율·요일·상한을 정합니다.

기본값은 **풀 100 = 200원, 토요일, 한 번에 최대 500풀**입니다. 하루 풀 수입이 약 100이므로 주 수입이 약 700, 그중 최대 500을 바꿔 **주 1,000원**입니다. 집 사정에 맞게 바꾸세요.

#### 바꾼 기록은 지우지 않습니다

소원권과 같습니다. 아이가 화면을 부모에게 보여주고, 부모 화면에도 날짜·금액·합계가 남습니다.

#### 이것이 마지막 소비처입니다

캐릭터 5종(88별)과 배경 10종(83별)은 언젠가 다 삽니다 — 시뮬레이션에서 **140일**입니다. 아이템 30종(9,450풀)도 **180일**이면 다 삽니다. 소원권과 용돈만 고갈되지 않습니다.

| 화폐 | 유한한 소비처 | 마르는 날 | 무한한 소비처 |
|---|---|---|---|
| ⭐ 별 | 캐릭터 88 + 배경 83 | 140일 | **소원권** |
| 🌿 풀 | 아이템 9,450 | 180일 | **용돈** |

### 8.6 만들지 않는 것

**랜덤 상자(가챠)는 넣지 않습니다.** 확률형 보상은 초등 3학년에게 이르고, "운이 나빴다"는 실패 경험을 만듭니다. 원하는 것을 모아서 사는 구조만 유지합니다.

**캐릭터마다 따로 사게 만들지 않습니다.** 8.7을 보세요.

### 8.7 아이템 소유 규칙 — 공용과 전용 (2026-08-19 결정)

아이템에는 두 종류가 있습니다.

| | 공용 | 전용 |
|---|---|---|
| 몇 개 | 15 (모자 7, 목도리 6, 소품 2) | 15 (캐릭터당 모자·목도리·소품 1개씩) |
| 사면 | **모든 캐릭터**가 쓸 수 있음 | 그 캐릭터만 |
| 언제 살 수 있나 | 상점 단계가 열리면 | 단계 + **그 캐릭터를 해금했을 때** |
| 상점 단계 | 1~2 | 3~5 |

#### 왜 "캐릭터마다 따로 사기"가 아닌가

전 아이템을 캐릭터별로 사게 하면 풀 소비처가 다섯 배가 되어 8장의 "풀이 남는다" 문제가 단번에 풀립니다. 진지하게 검토했고, **반대합니다.** 이유가 셋입니다.

**1. 아이가 캐릭터를 안 바꾸게 됩니다.** 양에 450풀짜리 왕관을 씌워놨는데 고양이로 바꾸면 맨머리입니다. 그러면 안 바꿉니다. **캐릭터를 다섯 종 만든 이유가 사라집니다.**

**2. 해금의 기쁨이 깎입니다.** 지금은 고양이를 만나자마자 가진 왕관을 씌워볼 수 있습니다. 개별 구매면 새 친구가 빈손으로 등장합니다. "늘어난 식구가 보이는 것이 장기 동기의 핵심"(4.1)이라고 한 그 순간이 약해집니다.

**3. 원칙 2.1의 정신에 걸립니다.** "어제 산 왕관인데 고양이한테는 없다"는 회수가 아니지만 **회수처럼 느껴집니다.**

#### 전용 아이템이 같은 문제를 푸는 방법

전용 15개와 공용 소품 2개를 더하면 총액이 2,430 → 9,450이 됩니다. 개별 구매가 노리던 소비처 확대를 부작용 없이 얻습니다.

게다가 **"이 친구를 데리고 다녀야 할 이유"** 가 생깁니다. 개별 구매가 만들려던 것이 사실은 이것이었고, 전용 아이템은 그것만 정확히 만듭니다.

#### 전용 아이템 (제안)

성격이 드러나는 것으로 고릅니다. 그 캐릭터가 아니면 어색해야 전용인 이유가 있습니다.

| 캐릭터 | 모자 (3단계) | 목도리 (4단계) | 소품 (5단계) |
|---|---|---|---|
| 양 | 꽃 화관 | 뜨개 목도리 | 작은 종 |
| 고양이 | 달 모자 | 생선 목걸이 | 요술 지팡이 |
| 토끼 | 귀 리본 | 당근 목걸이 | 네잎클로버 |

#### 아직 못 만난 친구의 전용 아이템은 상점에 안 보입니다

상점은 **지금 살 수 있는 곳**입니다. 다음 목표를 보여주는 일은 홈 화면의 회색 실루엣이 이미 하고 있습니다(`구현-현황.md` 2.6). 두 곳에서 같은 일을 하면 상점이 잠긴 물건 창고가 되고, 살 수 없는 것이 살 수 있는 것보다 많아집니다.

#### 소품 슬롯을 엽니다

`equipped: { hat, neck, prop }`의 `prop`이 스키마에 있는데 안 쓰이고 있습니다. 전용 아이템이 캐릭터당 셋이 되려면 슬롯도 셋이어야 하므로 여기서 엽니다. 공용 소품 2개는 2단계에 들어갑니다.

## 12. 문제 유형 (확장)

아이가 요청한 것 — **단답형, 서술형, 영어 단어**. 셋 다 "골라서 맞히기"만으로는 안 되는 영역입니다.

4지선다는 *재인(recognition)*을 훈련합니다. 보기를 보면 답이 떠오르는 상태입니다. 그런데 구구단에서 우리가 고치려던 것이 정확히 그 문제였습니다 — **노래로는 아는데 물으면 안 나오는 상태**. 영어 철자, 한자, 용어 정의는 4지선다로는 영영 인출 단계로 안 갑니다.

그래서 유형을 늘리되, **늘어난 난이도가 실패 경험으로 바뀌지 않게** 하는 것이 이 장의 전부입니다.

| 유형 | 파일 표기 | 답하는 법 | 채점 | 마스터리·별 |
|---|---|---|---|---|
| 선택 | `선택` (기본) | 보기 4개 중 하나 | 문자열 일치 | 적용 |
| 단답 | `단답` | 글자·숫자를 직접 입력 | 정규화 후 일치 (관대하게) | 적용 |
| 서술 | `서술` | 문장으로 씀 | **하지 않음** | 적용 안 함 |

아무것도 안 적으면 `선택`입니다. **기존 팩과 내장 구구단은 한 글자도 안 바꿔도 그대로 돕니다.**

### 12.1 단답형

#### 새로 생기는 위험

4지선다에는 아이가 **아무것도 안 하고 멈출 방법이 없습니다.** 모르면 아무거나 눌러도 25%고, 눌러야 다음으로 갑니다. 단답형에는 그 바닥이 없습니다. 빈칸 앞에서 멈춘 아이는 곧 "안 할래"가 됩니다. 이 게임이 없애려던 바로 그 상태입니다.

#### 세 가지 안전장치 (셋 다 필수)

**1. 「보기 보여줘」 버튼 — 언제든 선택형으로 내려올 수 있다**

단답형 화면에는 항상 `보기 보여줘` 버튼이 있습니다. 누르면 그 문제가 4지선다로 바뀝니다.

- 기본 보상은 동일합니다 (원칙 2.3 — 힌트가 무료인 것과 같은 이유)
- 마스터리는 **힌트 쓰고 정답과 같은 취급** (`m`이 0이면 1로, 아니면 유지)
- 화면에 "포기"라고 쓰지 않습니다. 그냥 다른 방법입니다

이 버튼 하나가 단답형의 바닥을 만듭니다. **막힌 아이에게 늘 누를 것이 있어야 합니다.**

**2. 관대한 채점**

다음은 전부 정답으로 봅니다.

- 앞뒤 공백, 문장 중간의 여분 공백
- 영어 대소문자 (`Apple` = `apple`)
- 영어 관사 (`a book` = `book`)
- 한글 조사만 다른 경우는 **판정하지 않고 파일에서 복수 정답으로 적게** 합니다 (`빛/빛깔`)
- 복수 정답은 파일에서 `/`로 구분

> 오타 때문에 틀린 것으로 처리되면, 아이는 *아는데 틀렸다*를 배웁니다. 그건 이 게임에서 가장 나쁜 결과입니다. 애매하면 정답 쪽으로 기울이세요. 관대해서 생기는 손해는 마스터가 조금 빨라지는 것뿐입니다.

**3. 빨간 밑줄 금지**

입력창에 브라우저 맞춤법 검사가 켜져 있으면 **아이가 쓰는 도중에 빨간 밑줄이 그어집니다.** 원칙 2.1 직격입니다. 영어 단어 입력에서는 거의 항상 뜹니다.

`spellcheck=false`, `autocorrect=off`, `autocapitalize=off`를 반드시 지정합니다. 자동 완성도 끕니다 — 답을 대신 채워주면 문제가 사라집니다.

#### 넘어가기

입력이 비어 있어도 `모르겠어`로 넘어갈 수 있고, **푼 것으로 셉니다.** 기본 보상이 나갑니다(원칙 2.2). 마스터리는 오답과 같이 처리합니다.

#### 보상

정답 보너스는 선택형과 **같습니다.** "쓰면 더 준다"를 만들면 쓰는 것이 부담이 됩니다.

### 12.2 서술형

#### 무엇을 묻나

"왜 그럴까?", "네 말로 설명해봐", "오늘 배운 걸 한 줄로". 정답이 하나가 아닌 것들입니다.

#### 가르치되 채점하지 않습니다

원칙 2.10입니다. 선생님이 조언은 하지만 **점수는 어디에도 남지 않습니다.**

서술형은 **마스터리·별·스티커의 대상이 아닙니다.** 채점이 없으니 `m`을 올릴 근거가 없고, 억지로 붙이면 AI 판정이 별로 환산됩니다 — 원칙 2.2가 무너지는 지점입니다.

> 이 분리가 조언을 허용할 수 있게 만드는 구조입니다. 선생님 말이 보상에 전혀 영향을 못 주기 때문에,
> 아이 입장에서 조언은 **잃을 것이 없는 정보**입니다. 채점과 조언을 같이 붙이면 조언이 감점 사유로 읽힙니다.

| | 선택·단답 | 서술 |
|---|---|---|
| 풀 🌿 | 기본 + 정답 보너스 | **기본만** (쓰면 지급) |
| 별 ⭐ | 마스터 시 1 | 없음 |
| 마스터리 `m` | 오르내림 | 없음 |
| 도감 | 스티커 판 | **이야기 판** (별도, 13.4) |

#### 하루 최대 2문제

서술형은 부담이 큽니다. 하루 목표 20문제가 전부 서술형이면 아이는 다음 날 안 옵니다. **하루 2문제까지만 섞습니다.** 그 이상은 부모가 자유 모드로 지정했을 때만.

#### AI 없이도 동작해야 합니다

서술형은 **AI가 꺼져 있어도, 인터넷이 끊겨도 완전히 동작합니다.** 아이는 쓰고, 보상을 받고, 선생님이 준비된 한마디를 하고, 글은 저장됩니다. AI는 그 한마디를 *상황에 맞게* 만드는 선택 기능입니다.

이 순서를 뒤집으면 안 됩니다. AI를 전제로 만들면 무료 크레딧이 떨어진 날 게임이 멈춥니다.

준비된 문장은 `content/messages.csv`의 `선생님 / 글쓰기` 줄입니다. 조언이 없는 일반적인 반응이라 어떤 글에도 어색하지 않아야 합니다 — *"잘 썼네. 다 읽었어."* 정도.

#### 내가 쓴 이야기

아이가 쓴 글은 프로필에 저장되고, 아이 화면 `내가 쓴 이야기`에서 다시 볼 수 있습니다. 날짜순으로 쌓입니다.

비교 대상이 **어제의 자신**뿐인 화면입니다(원칙 2.8). 초3이 3월에 쓴 두 줄과 12월에 쓴 다섯 줄을 나란히 보는 것은, 어떤 점수보다 강한 성장 증거입니다. 부모 화면에서도 같은 글을 봅니다 — 단, **고치라고 말하지 않기**를 안내에 적습니다.

### 13.1.1 조언 스위치

부모 화면에 스위치가 하나 있습니다. **기본 켜짐**입니다 — 원칙 2.10의 관찰에 따른 것입니다.

| 스위치 | 선생님이 하는 말 |
|---|---|
| **조언 켜짐** (기본) | 잘한 것을 짚고 → 다음에 해볼 것 **하나**를 제안 |
| 조언 꺼짐 | 잘한 것을 짚기만 함. 제안 없음 |
| AI 꺼짐 | `messages.csv`의 준비된 문장 |

**세 단계 전부 아이 눈에는 같은 선생님입니다.** 말이 조금 짧아질 뿐, 화면이 달라지거나 기능이 사라지지 않습니다. 부모가 되돌릴 때 아이가 "뭔가 없어졌다"를 느끼면 안 됩니다.

내리는 판단 기준: **아이가 서술형을 피하기 시작하면** 조언부터 끕니다. 그래도 안 되면 AI를 끕니다.

### 13.1.2 나중에 검토할 것 — 「선생님한테 물어보기」

아이가 스스로 부를 때만 선생님이 설명해주는 버튼입니다. 힌트(원칙 2.3)의 확장이고, "선생님 지시는 기꺼이 따른다"는 관찰과 정확히 맞물립니다.

넣는다면 경계는 이렇습니다. **자유 대화가 아닙니다.**

- 아이가 글을 입력하지 않습니다. 버튼만 누릅니다
- 지금 화면에 떠 있는 **그 문제 하나**에 대해서만
- 한 문제에 한 번
- 눌러도 보상은 그대로 (힌트와 같음)

지금은 만들지 않습니다. 서술형(6C·6D)이 자리를 잡은 뒤에 아이 반응을 보고 결정합니다.

> **아이가 쓴 글이 Google 서버로 전송됩니다.**
> 무료 등급은 보낸 내용이 서비스 개선에 쓰일 수 있습니다. 유료 등급과 다릅니다.

**부모가 이 내용을 검토하고 수용했습니다.** 이 프로젝트에서는 더 논의하지 않습니다. 설정 화면에 사실만 한 줄 적어두고, 켜고 끄는 것은 부모가 판단합니다.

아래는 비용이 거의 없어서 그냥 지키는 것들입니다. 방침이 바뀐 것이 아니라 **기본 위생**입니다.

- **아이 이름을 보내지 않습니다.** 프로필 이름·`{이름}` 치환자를 프롬프트에서 제거합니다
- 보내는 것은 **문제 · 아이가 쓴 답 · 선생님 말투 지시**뿐입니다
- 주고받은 내용을 로컬에 남겨 부모가 `/parent`에서 확인합니다 — 조언이 원칙 2.10을 지키는지 보려면 이게 필요합니다
- 하루 호출 상한을 서버가 강제합니다. 넘으면 조용히 폴백합니다 (무료 크레딧 보호가 목적)

### 13.4 이야기 판

서술형을 쓸 때마다 이야기 스티커 한 장. 12칸을 채우면 별 3 — 도감(8.4)과 같은 규칙입니다.

**쓰기만 하면 받습니다.** 잘 썼는지는 아무도 보지 않습니다. 이것이 서술형에서 유일하게 별과 연결되는 경로이고, 연결 고리는 *내용*이 아니라 *횟수*입니다.

> 별 페이싱 주의: 이야기 판은 별 소비처가 아니라 **공급처**입니다. 넣기 전에 60일 시뮬레이션을 다시 돌리세요 (`구현-현황.md` 6장). 하루 2문제 상한이면 판 하나에 6일이라 60일에 별 30 — 적지 않습니다.

## 14. 영어 단어 — 사진으로 등록하기

### 14.1 왜 사진인가

영어 단어는 매주 20~30개씩 새로 나옵니다. 부모가 매주 CSV에 손으로 치면 **3주면 안 하게 됩니다.** 이 게임의 성공 기준 3번("부모가 개발자 도움 없이 문제를 추가할 수 있다")이 실제로 깨지는 지점이 여기입니다.

단어장·시험지·교과서 페이지를 폰으로 찍으면 단어와 뜻이 표로 뜨고, 고쳐서 저장하면 팩이 됩니다.

### 14.2 반드시 부모가 확인한 뒤 저장합니다

**인식 결과를 그대로 저장하지 않습니다.** 이건 편의 문제가 아니라 원칙 문제입니다.

`purpose`를 `porpose`로 잘못 읽은 단어가 아이에게 나가면, 아이는 맞게 쓰고 틀렸다는 판정을 받습니다. 이 게임이 유일하게 절대 해서는 안 되는 일입니다.

흐름은 항상 이렇습니다.

```
부모 폰으로 촬영  →  표로 인식 결과 표시  →  부모가 고치고 지우고 추가
                                          →  확인 눌러야 content/problems/ 에 저장
```

읽기 애매한 칸은 표에서 **표시해 둡니다.** 부모가 어디를 볼지 알 수 있게.

### 14.3 문제 형태

| 방향 | 예 | 유형 |
|---|---|---|
| 영 → 한 | `apple` → 사과 | 선택 (보기는 같은 묶음의 다른 뜻) |
| 한 → 영 | 사과 → `apple` | 선택 |
| 철자 쓰기 | 사과 → 직접 입력 | 단답 |

한 단어에서 세 문제가 나오지만 **전부 내지는 않습니다.** 처음엔 영→한만, 마스터하면 한→영, 그 다음 철자 쓰기 — 같은 단어가 단계적으로 어려워집니다. 부모가 파일에서 방향을 고를 수도 있습니다.

오답 보기는 **같은 묶음(= 같은 주차 단어)의 다른 뜻**을 씁니다. 이미 구현돼 있는 규칙입니다(`구현-현황.md` 2.2). 그래서 **한 번 찍은 한 장이 곧 하나의 묶음**이 되게 파일을 나눕니다.

### 14.4 아이 화면은 변하지 않습니다

사진 촬영·인식·검토는 전부 부모 화면입니다. 아이에게는 어느 날 `3학년-영단어-9월2주` 팩이 하나 늘어나 있을 뿐입니다.

이것은 5A(문제 켜고 끄기)와 같은 성격의 작업입니다 — **부모의 도구를 늘리되 아이 화면은 건드리지 않는다.** 그래서 위험이 낮고, 먼저 만들기에 적합합니다.

## 15. 확장 순서와 판단 근거

아이가 원한 순서(단답 → 서술 → 영단어)가 아니라 **원칙을 깰 위험이 낮은 순서**로 만듭니다.

| 순서 | 무엇 | 아이 화면 | 외부 의존 | 원칙 위험 |
|---|---|---|---|---|
| 1 | 단답형 | 새 입력 화면 | 없음 | 낮음 (12.1 안전장치 3개로 통제) |
| 2 | 사진 등록 · 영단어 | **변화 없음** | AI 키 | 낮음 (부모 화면 전용) |
| 3 | 서술형 (AI 없이) | 새 쓰기 화면 + 선생님 등장 | 없음 | 중간 |
| 4 | 서술형 AI 반응·조언 | 선생님 말풍선만 | AI 키 | **높음** (원칙 2.10) |

사진 등록을 서술형보다 먼저 두는 이유는, **API 키 설정·실패 폴백·호출 상한을 부모 화면에서 먼저 검증**할 수 있기 때문입니다. 아이에게 아무것도 안 보이는 곳에서 인프라를 깔고, 그게 안정되면 아이 화면에 붙입니다.

각 단계 끝에서 11장의 성공 기준 5번을 다시 봅니다 — **틀리는 것에 대한 거부 반응이 줄어들고 있는가.** 단답형을 켠 뒤 힌트·「보기 보여줘」 사용률이 오르는 것은 좋은 신호입니다. 세션 이탈이 늘면 되돌리세요.

6D에서 볼 것은 하나 더 있습니다 — **조언을 켠 뒤 서술형에 쓰는 글이 짧아지지 않는가.** 글자 수가 줄면 선생님 말이 지적으로 읽히고 있다는 뜻입니다. 그때는 조언 스위치를 먼저 끕니다(13.1.1). 부모 화면의 AI 로그에서 그 주의 조언 문장을 직접 읽어보는 것이 가장 빠른 확인입니다.

## 16. 학습 진도 관리 (부모)

### 16.1 지금 무엇이 문제인가

문제 파일이 `content/problems/` 폴더에 **평평하게** 놓입니다. 파일 하나가 팩 하나이고, 그게 전부입니다.

문제가 60개일 때는 괜찮았지만, 부모가 실제로 쓰려는 방식은 이렇습니다.

```
수학    1-1 구구단
        1-2 2자리 × 1자리 곱셈
        1-3 나눗셈
        1-4 나머지가 있는 나눗셈
한국사  1-1 구석기~신석기
        1-2 청동기~철기
```

**과목 → 단원 → 문제**의 두 단계 계층이고, 순서에 의미가 있습니다. 지금 구조로는 셋이 안 됩니다.

| 안 되는 것 | 왜 |
|---|---|
| 과목으로 묶기 | 계층이 없습니다. 파일명에 `수학-`을 붙이는 관습이 전부입니다 |
| 순서대로 열기 | `1-10`이 `1-2`보다 앞에 옵니다. 문자열 정렬이라서입니다 |
| "1-3까지 열기" | 팩을 하나씩 체크 해제해야 합니다. 20개가 되면 못 씁니다 |
| 다음 학기 파일 미리 넣기 | 넣는 순간 아이에게 나갑니다 |

마지막이 제일 큽니다. **아직 학교에서 안 배운 문제가 나오면 안 됩니다.** 그건 이 게임이 지키려는 것과 정면으로 부딪힙니다.

### 16.2 폴더가 곧 과목입니다

```
content/problems/
├─ 수학/
│   ├─ 1-1 구구단.csv
│   ├─ 1-2 2자리 곱셈.csv
│   ├─ 1-3 나눗셈.csv
│   └─ 1-4 나머지가 있는 나눗셈.csv
├─ 한국사/
│   ├─ 1-1 구석기~신석기.csv
│   └─ 1-2 청동기~철기.csv
└─ 나눗셈.csv          ← 폴더 밖은 지금처럼. 과목 없음, 진도 관리 안 함
```

- **폴더 이름 = 과목.** 설명이 필요 없습니다. 부모가 탐색기에서 보면 바로 압니다
- **파일명 앞의 `1-1` = 단원 번호.** 정렬 키이자 화면에 보이는 이름
- **폴더 밖의 파일은 지금 그대로** 동작합니다. 항상 열려 있고 진도 관리 대상이 아닙니다

기존 파일을 옮길지 말지는 부모가 정합니다. 안 옮겨도 게임이 그대로 돕니다.

> 파일 안에 `과목:` 줄을 넣는 방법도 검토했지만 폴더가 낫습니다. 부모가 **파일 탐색기에서 직접 보고 이해**하는 것이 이 프로젝트의 조건입니다(성공 기준 3). 폴더는 그 자체로 설명입니다.

### 16.3 진도는 과목마다 "여기까지"

부모 화면에서 과목마다 한 곳을 찍습니다.

```
수학          여기까지 열기  [1-3 나눗셈 ▼]
   1-1 구구단              15문제 · 완전히 외운 것 12
   1-2 2자리 곱셈          20문제 · 완전히 외운 것 5
   1-3 나눗셈              24문제 · 완전히 외운 것 0
   ─────────────────────────  아직 안 열림
   1-4 나머지가 있는 나눗셈  18문제
```

체크박스 20개가 드롭다운 하나가 됩니다. 그리고 **뒤에 새 파일을 넣어도 안 열립니다** — 다음 학기 분량을 미리 준비해둘 수 있습니다.

기본값은 **첫 단원만**입니다. 부모가 파일을 넣어두고 진도에 맞춰 여는 것이 이 기능의 목적이므로, 넣자마자 다 열리면 안 됩니다.

진도는 **프로필마다** 따로입니다. 형제자매는 학년이 다릅니다.

### 16.4 되돌릴 때 — 진도는 줄일 수 있습니다

상점 단계·별·스티커와 달리 **진도는 내릴 수 있습니다.** 아이가 아직 어려워하면 부모가 한 단원 접어둘 수 있어야 합니다.

내려도 사라지는 것은 **앞으로 그 문제가 안 나온다**는 것뿐입니다. `facts`의 진도, 받은 별, 도감 스티커, 열린 상점 단계는 **전부 그대로**입니다 — 5A의 문제 켜고 끄기와 같은 규칙입니다(원칙 2.1).

부모 화면에 그 문장을 그대로 띄웁니다.

### 16.5 아이 화면에는 열린 것만 보입니다

**안 열린 단원을 회색으로 보여주지 않습니다.** 목장의 회색 실루엣(다음에 만날 친구)과는 다릅니다.

| | 회색으로 보여주는가 | 왜 |
|---|---|---|
| 다음에 만날 친구 | **예** | 아이가 별을 모아서 **스스로 여는 것**. 목표가 됩니다 |
| 아직 안 배운 단원 | **아니오** | **학교가 여는 것**. 아이가 통제할 수 없습니다 |

아이가 통제할 수 없는 것을 눈앞에 두면 목표가 아니라 압박입니다.

### 16.6 새 단원이 열리면 아이 화면에 알립니다

부모가 진도를 올리면 홈 화면에 **"새로운 문제가 왔어!"** 가 뜹니다. 상점 단계가 열릴 때와 같은 방식입니다(8.3).

학교에서 새 단원을 배운 날 부모가 열어주면, 게임에서 그것이 사건이 됩니다. **부모가 진도를 챙기는 일이 아이에게는 선물이 됩니다.**

### 16.7 자동으로 열지 않습니다

앞 단원을 다 마스터하면 다음을 자동으로 여는 방식은 **만들지 않습니다.** 게임이 학교보다 앞서가면 아이가 안 배운 것을 풀게 됩니다.

대신 부모 화면이 **제안**합니다 — *"1-3을 다 외웠어요. 1-4를 열까요?"* 여는 것은 부모가 누릅니다.

### 16.8 자유 모드는 두 단계가 됩니다

과목이 둘 이상이면 아이 화면의 "무엇을 풀까?"가 두 단계로 갈립니다.

```
다 섞어서 / 수학 / 한국사
   └ 수학 전체 / 1-1 구구단 / 1-2 2자리 곱셈 / 1-3 나눗셈
```

과목이 하나뿐이면 지금처럼 한 단계입니다. 열린 단원만 나옵니다(16.5).

### 16.9 곁들여 따라오는 것

- **단원 완주에 별 5** — 이미 있는 규칙입니다(8.2 "팩 하나 전체 마스터"). 단원 단위가 되면 훨씬 자주, 훨씬 의미 있게 발생합니다
- **별 수입이 늘어납니다** — 단원이 늘면 마스터 대상 문제가 늘어납니다. 소원권(8.8)이 그 뒤를 받지만, **넣기 전에 60일 시뮬레이션을 다시 돌려야 합니다**
- **"다시 만나기"(6.2)가 단원을 넘나듭니다** — 지난 단원 복습이 자연스러워집니다. 7단계에서 다룹니다
